# Security and privacy

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/EdgarHnd/Burro/security/advisories/new). Include the affected version/commit, a minimal synthetic reproduction, impact, and any suggested fix. Do not put vulnerabilities, credentials, provider databases, or live transcripts into public issues.

The latest version on the default branch is the supported development version. There is no promised response time or long-term support schedule yet.

## Trust model

Burro is an unsandboxed macOS app running as the current user. It reads Git state, same-user process information, and Codex/Claude metadata using normal filesystem permissions. It does not request Accessibility or Input Monitoring permissions for normal operation.

- Git inspections never fetch or clean up automatically. Explicit confirmed cleanup rechecks activity, protection, registration identity, HEAD, branch, commit retention on a verified local branch, and Git facts, moves the entire directory to macOS Trash, then unregisters only that missing worktree using `git worktree remove -- path` without force. It does not delete branches or prune other registrations. Ignored data is preserved, not considered safe to discard. Replacement directories and changed registrations abort unregistering; failures report the retained Trash location. Codex-managed worktrees are excluded. Batch actions require an explicit selection and confirmation; every item uses the same fresh safety checks. Optimistic row removal is presentation only. Failures restore rows, and stopping a batch skips queued items without interrupting a filesystem operation already in progress. Status checks disable optional locks and fsmonitor. Commit retention is rechecked after the move; integration hints never authorize removal. Cleanup labels are point-in-time observations; fresh checks reduce but cannot eliminate races with other processes.
- Provider databases are opened read-only. Bounded transcript tails are parsed for lifecycle events; message bodies are not retained or exported. Authentication files are outside the agent/session readers' scope.
- Optional usage monitoring invokes only read-only account methods on the installed Codex app server and makes fixed HTTPS GETs to Anthropic usage/profile and Grok CLI billing/settings endpoints, plus the read-only Grok GetGrokCreditsConfig RPC fallback using selected coding-app sign-ins. Tokens stay in memory, never in logs or Burro storage. Redirects, cookies, and response caching are disabled. Background Keychain access cannot prompt; only Connect Claude may request native permission. Burro never independently rotates provider refresh tokens or imports browser sessions. Recovery delegates to Codex’s account refresh and Grok’s bounded noninteractive model-list utility; those official tools may renew their own credential stores. Claude Code remains responsible for Claude renewal. When its Keychain grant resets or its token expires, Burro can delegate to the installed CLI’s built-in noninteractive `/usage` command while the login Keychain is known unlocked. This asks the credential owner for quotas, never exported credentials. It sets zero allowed model turns, disables tools/hooks/configured MCP servers and session persistence, uses a private temporary directory, strips credential/endpoint overrides, preserves the selected profile and nonessential-traffic policy, and bounds execution/output. Only successful zero-turn structured quota results are accepted; no account identity is inferred and no quota history is recorded from that report. Grok renewal uses the selected profile, strips API-key overrides, suppresses I/O, coalesces concurrent attempts, and verifies credentials again after completion. A separately confirmed Account action launches official CLI sign-in in Terminal, which changes that provider’s coding-app account. Generated login scripts contain no credentials, quote selected paths, have private permissions, and delete themselves after exit. Disabling Usage clears the view and discards in-flight results. See [setup and supported sign-ins](docs/usage.md#usage-limits).
- Remote monitoring uses the user's existing OpenSSH trust and authentication. Hosts are explicitly configured; strict known-host checks, batch authentication, fixed commands, and disabled forwarding are required. Burro does not install a service or copy provider credentials to remote machines.
- Paths, titles, agent states, and completion metadata may travel from configured hosts to this Mac over SSH. Local unread lists are not sent to remote hosts.
- Optional quota history stores only limit samples and a hashed account identifier in a private local file, bounded to 30 days / 15,000 samples. It is never used as live fallback; disabling history deletes it. The on-demand local cost scanner reads bounded token records, ignores message content, keeps aggregates in memory, and performs no network requests.
- Preferences store provider/profile choices and usage display settings, repository roots, protection flags, comparison refs, notch settings, and explicit remote host configuration. Session metadata is held in memory. The CLI prints paths and titles, so redact output before sharing it.
- Provider storage schemas and URL routes are private interfaces. Unsupported or incomplete data must remain visible as uncertainty, never become evidence that deletion is safe.

A user-controlled SSH configuration can itself invoke programs such as ProxyCommand. Only add SSH hosts/configuration you trust. Burro is not an isolation boundary for a malicious local account, repository configuration, or remote host.

## Distribution

The public release contains source. Local build scripts reuse an existing Apple Development identity when available (or an explicitly configured identity), with ad-hoc fallback; this is not Developer ID distribution signing or Apple notarization. Do not treat an independently supplied Burro binary as an official signed release. CI does not publish app bundles or require signing credentials.
