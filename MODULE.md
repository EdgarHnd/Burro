# Burro architecture

## Ownership

- `script/generate_brand.swift`: single vector geometry source for the Butter and Abstract mascots, producing production PDFs and transparent PNG/SVG previews. `BurroBrand.swift` loads the butter PDF for the native menu bar; the app icon generator consumes that same PDF. `BurroMascotView` uses separate body/plate PDFs and exported eye geometry for compositor-driven blinking, glances, hops, squash, and tilts. `BurroMascotMotion` keeps poses inside the original frame and the plate stationary. `AgentAvatar` supplies orange Claude/blue Codex tints and a stable per-session timing offset; stale sessions stay still and idle sessions have quieter motion. It stops while collapsed, hidden, clipped, detached, or under Reduce Motion; activity polling does not restart the blink. No animation timer, per-frame SwiftUI update, geometry expansion, or input interception. The build packages and verifies the `Burro_Burro.bundle` assets.

- `Sources/Burro/Notch/NotchGlassView.swift`: one native material for the expanded notch, using `NSGlassEffectView` on macOS 26+ and behind-window `NSVisualEffectView` on earlier versions. `NotchSurfaceView` clips and fades it with the existing outline, hides it while collapsed or under Reduce Transparency, and keeps input routed to the SwiftUI hosts. Camera-area black and nonactivating panel geometry remain unchanged.

- `Sources/Burro/Support/AppAppearance.swift`: shared charcoal palette, compact typography, provider badges, card surfaces, and role-aware pill buttons across worktrees, sidebar, inspectors, remote sessions, Usage, settings, cleanup sheets, and notch content. Native window chrome uses dark Aqua; the notch camera area remains black. Existing sizes, keyboard actions, percentage direction, stale states, safety checks, and panel geometry stay with their existing components.

- `Rust/src/main.rs`: parent-owned `burro-log-worker` stdio executable, the parent protocol and Codex monitoring component. Protocol-v3 JSON requests contain selected Codex log paths and/or a bounded Claude scan request. It reads at most 512 KiB per file, returns lifecycle summaries and file modification times, and caches summaries by device/inode/size/nanosecond modification and change times. Raw transcript bytes are never cached or returned. Appends, truncation, replacement, deletion, and changes during reads invalidate evidence; non-regular files and final-component symlinks are rejected. Cache entries are limited to the current batch (at most 2,048 paths). EOF exits the worker; no listener, daemon, provider credentials, or filesystem writes.
- `Rust/src/claude.rs`: protocol-v3 Claude batches contain a projects root, verified idle session UUIDs/incarnation times, and the current time. Index up to 4,096 project entries once per batch, inspect up to 256 worker logs per session within 1.2 seconds, reject symlinks/non-regular logs, and retain at most 4,096 identity-keyed lifecycle summaries. Freshness is reevaluated on cache hits; terminal handbacks, future timestamps, incomplete scans, and file mutation stay conservative. Swift fallback and remote Python share the project-limit/lifecycle policy. No transcript text crosses the pipe.
- `Rust/src/usage.rs`: separate on-demand history worker with a 20-second scan budget, 20,000 visited entries, 32 MiB files, 256 MiB logical scan budget, 200,000 counter records, and 512 aggregate response buckets. At most 8,192 files / 200,000 parsed records are cached. Discover bounded file candidates and spend the read budget on recently modified transcripts first. Deduplicate provider counters before local-calendar day/model aggregation; retain partial coverage markers. Swift supplies calendar boundaries and reference pricing. No credential reads or transcript text in responses/caches.
- `Rust/src/completed.rs`: bounded Claude desktop metadata scan deserializes only session ID, completion count and archive flag. Cache validated summaries by file identity; incomplete scans fall back to Swift. Bounds: 8,192 visited entries, files below 1 MiB, 256 MiB read budget, 1.2 seconds and 2,048 returned IDs.
- `policy/session-status.json`: single source for Codex lifecycle/completion mappings, Codex age thresholds and Claude status aliases. `script/generate_status_policy.py --check` verifies generated adapters; `policy/status-fixtures.json` supplies independent cross-language expectations.
- `Sources/BurroCore/AgentRefreshCoordinator.swift`: native recursive file watcher, coalesced non-overlapping scans and bounded process-check fallback. Active/uncertain checks remain three seconds; quiet checks use fifteen seconds when the watcher is running. Events during scans schedule one follow-up; shutdown cancels pending work.
- `Sources/BurroCore/AgentLogWorker.swift`: serialized child supervision and Swift recovery reader. Each request/response is correlated and bounded (2 MiB request, 512 KiB response, two-second lifecycle / 22-second history exchange deadlines); protocol errors, crashes, and timeouts close/terminate the child, fall back to the Swift parser, and apply a 30-second restart cooldown. No inherited credential environment or shell. Release apps discover only the signed sibling executable. The debug build additionally recognizes the project-local Rust output. `AgentReader` batches selected Codex logs and independently rechecks writer locks and age-based state; worker failure never becomes an empty successful inventory. Claude transcript discovery/parsing runs in Rust; native process identity and descriptor inspection, provider authentication/networking, remote Python execution, and cleanup ownership remain in Swift/platform adapters.
- `script/build_rust_worker.sh`: locked release Cargo build using `rust-toolchain.toml`; the existing app builder includes and signs the worker before signing the app. Swift-only development remains supported through fallback; CI builds the worker and requires integration tests.

- `Sources/BurroCore/WorktreeCleanup.swift`: explicit recoverable cleanup policy and execution. Actionable cleanup statuses use verified local-branch retention independently of integration/publication; ignored data is allowed because all contents are retained. The legacy CLI assessment remains conservative. Fresh scan + identity/Git/activity checks precede the move; branch retention is checked again before and after moving; Codex-managed worktrees are excluded; no force, branch deletion, global prune, or automatic fetch. The main store serializes UI cleanup, disables protection changes during it, and refreshes after batch completion. Recovery and race limits: [cleanup contract](docs/usage.md#cleanup-and-recovery).
- `Sources/Burro/Stores/CleanupBatchStore.swift`: serialized queue with explicit queued/moving/moved/failed/skipped outcomes, optimistic path projection, stop-remaining, and in-memory recovery receipts. It delegates every mutation to the existing WorktreeCleanup actor; there is no safety bypass. AppStore owns multi-selection, confirmation, and a scan generation that invalidates older scans before queuing, then settles optimistic rows only after a fresh post-batch scan.
- `Sources/Burro/Views/CleanupStatusView.swift`: nonmodal progress/results strip, on-demand recovery detail sheet, and multi-selection inspector. Native Table multi-selection, Select ready, Command-Delete/Delete and contextual actions share the same batch review.
- `Sources/Burro/Views/WorktreeCleanupSheet.swift`: one selection-specific confirmation with skipped blockers and retained branches. WorktreeListView exposes folder/branch labels, primary blockers, cleanup filter, and repository-scoped totals. WorktreeDetailView owns the per-repository comparison picker and cleanup entry point.
- `Sources/BurroCore/NotchWorkspace.swift`: machine/path display grouping adapted from PR #1, preserving NotchFeed membership and unread semantics. Orphan-worker buckets have no asserted checkout. NotchView freezes workspace identities alongside held chat rows and shows checkout-level local-ref delivery without filtering on edits.

- `Sources/Burro/App`: app/window/menu bar scenes, macOS activation, and explicit runtime Dock icon from the declared bundle resource to avoid stale Launch Services artwork.
- `Sources/Burro/Views`: navigation, overview, evidence inspector, settings.
- `Sources/Burro/Stores/AppStore.swift`: main-actor state, independent Git (30 seconds) / local-agent (file changes with 3/15-second fallback) / remote-agent (10 seconds) refresh loops, local preferences, and native open/reveal actions. Remote results are accepted only when their original host configuration still matches; merged activity never enters the local cleanup scanner.
- `Sources/Burro/Notch/NotchController.swift`: one nonactivating `NSPanel`, screen/Space placement with cross-application fullscreen eligibility, live attention observation, passive local/global pointer movement observers, common-run-loop-mode hover deadlines, pin/collapse lifecycle, provider chat navigation on row click, and explicit dashboard routing. Hover uses global screen coordinates, not SwiftUI/native view enter/exit events. Native menu tracking temporarily extends hover ownership so options menus remain usable outside the panel bounds. The status-bar overlay level is applied after `isFloatingPanel`, which otherwise resets it. Event tokens and pending timers are removed on shutdown. SwiftUI reports measured tab bounds; the controller converts screen pointers to that coordinate space and shares one common-mode timer between panel and preview deadlines. Content resize callbacks defer to the next main-queue turn and combine pending requests, preventing reentrant hosting-view layout during SwiftUI rendering; shutdown cancels pending requests and unchanged geometry is not republished. Already-open page size changes update the native frame and clipping outline together; only opening/closing uses the outline spring, preventing a taller Usage preview from being cut off by the previous Agents outline. Local unified logs record only hover/expansion booleans and event source, never session metadata or coordinates.
- `Sources/Burro/Notch/NotchSurfaceView.swift`: a black `CAShapeLayer`, matching content mask, and two fixed-size SwiftUI hosts. Compositor keyframes own outline, opacity, and a small content translation. The controller grows the native canvas before opening and shrinks it after completion; generation checks ignore cancelled completions. A clipped, steady inner rim glows amber for input requests or blue for unread completions while collapsed. Short opacity/color fades honor Reduce Motion; the rim adds no window area, polling timer, or input target. Hit testing/accessibility explicitly select the active host because layer opacity alone does not hide an NSView from input.
- `Sources/Burro/Notch/NotchView.swift`: compact running-or-scheduled/attention indicators, slim attention queue, explicit worker disclosure, optional idle filtering, persistent Agents/Usage tabs with temporary hover previews, a separate Usage view with a five-row-height viewport, stable list reconciliation, and machine-scoped monitoring detail navigation. It never owns hover timing or animation. The expanded header retains butter; the compact view has no logo or idle fallback.
- `Sources/Burro/Notch/NotchAgentRow.swift`: fixed-height chat navigation targets with live status and disabled unavailable rows; a parent's worker attention is labeled explicitly.
- `Sources/Burro/Notch/NotchUsageView.swift`: compact Codex/Claude/Grok quota sections, remaining bars, per-provider source age, reset countdowns, explicit stale/expired/missing states, and explicit Claude connection / quota refresh actions. Agent status remains the default notch surface.
- `Sources/BurroCore/ProviderUsage.swift`: provider-neutral quota models, sanitized issue states, and bounded native Codex/Claude response decoders. Multi-bucket Codex values take precedence over the legacy view. Missing percentages/resets stay unknown; account identity, window durations, model quotas, and extra usage are explicit.
- `Sources/BurroCore/CodexUsageReader.swift`: current/legacy desktop CLI discovery before standalone installs and a short-lived, bounded app-server stdio client. Only initialize, account/read, and account/rateLimits/read are allowed. No shell, transcript, model request, listener, or credential export. A single 20-second deadline, 2 MiB output cap, and terminate/kill cleanup bound the child.
- `Sources/BurroCore/ClaudeUsageReader.swift`: read existing Claude Code credentials from the selected local profile or the default account’s exact Keychain item. Requires unexpired user:profile scope. Only the initial read from explicit Connect Claude can prompt; background and token-rotation retry reads forbid interaction. Sends GET to the fixed Anthropic HTTPS usage/profile endpoints with redirects/cookies/cache disabled and bounded response/timeouts. Credentials remain in memory and are never rewritten, independently refreshed, logged, or copied to Burro storage. A 401 triggers one same-profile reread/retry only if the token changed. Expiry or a reset Keychain grant can delegate to ClaudeCLIUsageReader; Claude Code owns renewal. Explicit prompt cancellation does not delegate. Custom profiles never fall back to the default account’s Keychain item. Synchronous credential reads use a dedicated dispatch queue, outside the cooperative executor shared by long-running worktree scans.
- `Sources/BurroCore/ClaudeCLIUsageReader.swift`: bounded, noninteractive, zero-turn `/usage` fallback through the credential owner. Only structured quota reports followed by a successful local-command result are decoded; no prose, transcript, token export, inferred account identity, or history merge. Hooks/tools/MCP/session persistence are disabled, profiles and traffic policy are preserved, and a locked/unknown login Keychain prevents launch. See the [usage connection contract](docs/usage.md#usage-limits).

Establish no-prompt mode before reading, fail closed if it cannot be set, and restore the previous mode on success or error. A read-only default-Keychain lock check distinguishes temporary lock from denied approval.

## Invariants

1. Background monitoring never mutates monitored repositories or provider configuration. Explicit confirmed cleanup may move an eligible local checkout to Trash and remove only its missing-folder registration, retaining the branch and ignored data; see WorktreeCleanup and the usage recovery contract. Optional usage recovery lets official Codex/Grok tools renew existing credentials. Network access is limited to configured SSH hosts and optional authenticated provider quota reads. No automatic Git fetch, forced cleanup, global prune, or installed hooks. Explicit confirmed sign-in may launch the official coding-app login.
2. Unknown checks and adapter errors cannot yield a safe candidate. Open idle agents are in use, not disposable.
3. Keep local-ref evidence distinct from verified live remote state. Safe candidate remains advisory.
4. Git commands use fixed executable paths and argument arrays. A repo path/ref is never interpolated into shell source. Read Git status with optional locks disabled and fsmonitor disabled.
5. Agent/session readers never access authentication stores or retain prompt/tool bodies. Direct usage is a separate, optional path: Codex handles its own authentication; Claude/Grok readers use only selected coding-app sign-ins for fixed provider endpoints. Never export/log/persist tokens, read browser cookies, or independently rotate provider-owned credentials. Grok’s fixed model-list utility and Codex’s account refresh can ask those providers to renew their own stores. Claude renewal stays with Claude Code; the bounded noninteractive `/usage` fallback runs only with an unlocked login Keychain, zero allowed model turns, tools/hooks/MCP disabled, and no saved conversation. It returns quotas, never credentials. No model request is sent. SSH uses existing OpenSSH authentication without importing it into Burro.
6. Manual protection adds a blocker; it cannot override dirty data or other evidence.
7. The frontend never executes shell commands supplied by branch names, filenames, or agent titles.
8. Notch/menu-bar activity is sampled independently of the full Git/worktree snapshot. The fast feed does not loosen cleanup advice between full scans. A session selection preserves the intended worktree when switching dashboard filters.
9. The notch does not take main-window status or activate the dashboard on hover. It uses no global keyboard monitor or provider hooks. Preference changes and screen/Space changes reconfigure the single app-owned panel; shutdown removes observers and the local Escape handler. `AgentNotchPanel.constrainFrameRect` deliberately preserves the frame computed by `NotchGeometry`; AppKit otherwise displaces even a borderless panel below the menu bar. Only the pin button makes expansion persistent; clicks and keyboard opening remain transient after the first pointer visit. Manual collapse does not order the window out and back in. Passive local/global mouse-movement observers remain active across application focus; no per-frame polling, keyboard monitoring, or provider hooks are involved. An 8-point approach margin opens immediately; a 10-point expanded margin and 120 ms exit deadline prevent edge flicker. The expanded interaction footprint remains available during closing for immediate reentry. Core Animation owns outline/fades without per-frame SwiftUI layout or NSWindow resize, preserving both position and velocity when retargeted. Reduce Motion skips interpolation. The native window releases its temporary expanded input footprint after completion. The hosting views disable automatic safe-area and content-size adjustments because geometry already reserves the camera. Safe top insets still reserve a conservative camera gap if auxiliary screen rectangles are unavailable.
10. Remote session IDs include their Burro host UUID; remote paths remain literal, and local worktree resolution refuses remote origins. Offline/expired samples become unknown and cannot count as working. No cloud relay or provider desktop pairing is reused. SSH uses strict host-key checks and batch authentication; the remote command is constant, and metadata never becomes a shell command.
11. Chat navigation only opens fixed provider URL schemes and routes derived from validated IDs. No prompt, folder, credential, CLI import/resume, or remote command is included. Claude remote bridge IDs may navigate the local app; another machine's local desktop ID must never do so.
12. Freeze list membership/order during expanded pointer or keyboard interaction. Keep metadata live, disable missing targets, and expose explicit refresh for pending membership changes. Unfreeze on pointer/key-focus exit; explicit filter/disclosure actions may change layout. Do not acknowledge provider unread markers or infer worker parents from paths/titles.
13. Restore original preferences once, copying only explicit repositories, protections, discovery, and comparison branches. Preserve any already-configured Burro values.

## Direct usage integration

Burro fetches independently of CodexBar. The Codex contract is generated from the installed app-server schema; the integration uses account/read and account/rateLimits/read. The Claude OAuth usage contract was checked against CodexBar’s [provider documentation](https://github.com/steipete/CodexBar/blob/main/docs/claude.md), but no upstream implementation or dependency is bundled. See [usage setup and limitations](docs/usage.md#usage-limits).

Fetches publish independently as each provider finishes and run in parallel outside the agent loops, at the selected one/five/fifteen-minute cadence automatically and 15 seconds on manual refresh. Poll deadlines are independent per provider: temporary errors retry with 30–300 second backoff, pending renewal is checked after 60 seconds, and rate limits impose at least five minutes even for manual refresh. Disabling Usage clears displayed values and invalidates in-flight results; re-enabling starts a new generation. Each failed provider clears its own previous values, preventing old account data from surviving an authentication failure. Optional account-scoped history persists only for charts; it is never a live quota fallback. Wake/session activation/app activation coalesce into a silent retry of transient failures; rate-limit backoff and healthy-provider cadence remain intact. Expired reset dates never imply a refill. Limits describe the local provider sign-ins and are shared across machines using those accounts, not attributed to individual chats or SSH hosts.

## Known boundaries

This is an unsandboxed, locally signed desktop utility (Apple Development when available, ad-hoc fallback): system process inspection and provider files require normal user read access. App Store sandbox packaging is not implemented. The app store owns the refresh task, so monitoring continues when the main window closes; individual subprocesses have deadlines. Monitoring cannot eliminate time-of-check/time-of-use races, observe unconfigured hosts or cloud tasks, or guarantee all processes are visible. Discovery is bounded rather than a full filesystem crawl; missing directories and private provider schema changes are reported where observable.

Unread integration boundaries and account-switch behavior are documented in [usage guide](docs/usage.md#done-and-unread-status). Keep the Swift and Python completion parsers consistent; completion evidence alone never implies unread.
