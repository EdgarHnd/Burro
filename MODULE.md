# Burro architecture

## Ownership

- `script/generate_brand.swift`: single vector geometry source for the Butter and Abstract mascots, producing production PDFs and transparent PNG/SVG previews. `BurroBrand.swift` loads the butter PDF for the native menu bar; the app icon generator consumes that same PDF. `BurroMascotView` uses separate body/plate PDFs and exported eye geometry for compositor-driven blinking, glances, hops, squash, and tilts. `BurroMascotMotion` keeps poses inside the original frame and the plate stationary. `AgentAvatar` supplies orange Claude/blue Codex tints and a stable per-session timing offset; stale sessions stay still and idle sessions have quieter motion. It stops while collapsed, hidden, clipped, detached, or under Reduce Motion; activity polling does not restart the blink. No animation timer, per-frame SwiftUI update, geometry expansion, or input interception. The build packages and verifies the `Burro_Burro.bundle` assets.

- `Sources/Burro/Notch/NotchGlassView.swift`: one native material for the expanded notch, using `NSGlassEffectView` on macOS 26+ and behind-window `NSVisualEffectView` on earlier versions. `NotchSurfaceView` clips and fades it with the existing outline, hides it while collapsed or under Reduce Transparency, and keeps input routed to the SwiftUI hosts. Camera-area black and nonactivating panel geometry remain unchanged.

- `Sources/Burro/Support/AppAppearance.swift`: shared adaptive palette (warm paper in light mode, charcoal in dark), compact typography, provider badges, card surfaces, and role-aware pill buttons across Home, worktrees, sidebar, inspectors, remote sessions, Usage, settings, cleanup sheets, and notch content. `AppearancePreference` (Settings → Appearance) sets `NSApp.appearance`; the notch panel pins dark Aqua so the camera area remains black, and `BurroMascotView` resolves tints against its own appearance. Existing sizes, keyboard actions, percentage direction, stale states, safety checks, and panel geometry stay with their existing components.

- `Rust/src/main.rs`: parent-owned `burro-log-worker` stdio executable, the parent protocol and Codex monitoring component. Protocol-v4 JSON requests contain selected Codex log paths and/or a bounded Claude scan request. It reads at most 512 KiB per file, returns lifecycle summaries and file modification times, and caches summaries by device/inode/size/nanosecond modification and change times. Raw transcript bytes are never cached or returned. Appends, truncation, replacement, deletion, and changes during reads invalidate evidence; non-regular files and final-component symlinks are rejected. Cache entries are limited to the current batch (at most 2,048 paths). EOF exits the worker; no listener, daemon, provider credentials, or provider-data writes.
- `Rust/src/catalog.rs`: read-only Codex metadata index using bundled SQLite. A persistent connection compares `PRAGMA data_version` on that same connection; a short transaction reads threads, project roots and worktree attachments consistently without pinning the WAL between refreshes. Main-file identity/stamp changes reopen it. Per-query bounds: 20,000 rows per table, 6 MiB serialized snapshot, 1.2-second progress deadline and 200 ms busy timeout. Only changed metadata crosses the pipe; missing/corrupt/replaced databases or worker restarts cannot revive cached snapshots. `CodexCatalog.swift` retains the recovery reader.
- `Rust/src/claude.rs`: protocol-v4 Claude batches contain a projects root, verified idle session UUIDs/incarnation times, and the current time. Index up to 4,096 project entries once per batch, inspect up to 256 worker logs per session within 1.2 seconds, reject symlinks/non-regular logs, and retain at most 4,096 identity-keyed lifecycle summaries. Freshness is reevaluated on cache hits; terminal handbacks, future timestamps, incomplete scans, and file mutation stay conservative. Swift fallback and remote Python share the project-limit/lifecycle policy. No transcript text crosses the pipe.
- `Rust/src/usage.rs`: separate on-demand history worker with a 20-second scan budget, 20,000 visited entries, 32 MiB files, 256 MiB logical scan budget, 200,000 counter records, and 512 aggregate response buckets. At most 8,192 files / 200,000 parsed records are cached. Discover bounded file candidates and spend the read budget on recently modified transcripts first. Deduplicate provider counters before local-calendar day/model aggregation; retain partial coverage markers. Swift supplies calendar boundaries and reference pricing. No credential reads or transcript text in responses/caches.
- `Rust/src/completed.rs`: bounded Claude desktop metadata scan deserializes only session ID, completion count and archive flag. Cache validated summaries by file identity; incomplete scans fall back to Swift. Bounds: 8,192 visited entries, files below 1 MiB, 256 MiB read budget, 1.2 seconds and 2,048 returned IDs.
- `policy/session-status.json`: single source for Codex lifecycle/completion mappings, Codex age thresholds and Claude status aliases. `script/generate_status_policy.py --check` verifies generated adapters; `policy/status-fixtures.json` supplies independent cross-language expectations.
- `Sources/BurroCore/AgentRefreshCoordinator.swift`: native recursive file watcher, coalesced non-overlapping scans and bounded process-check fallback. Active/uncertain checks remain three seconds; quiet checks use fifteen seconds when the watcher is running. Events during scans schedule one follow-up; shutdown cancels pending work.
- `Sources/BurroCore/AgentLogWorker.swift`: serialized child supervision and Swift recovery reader. Each request/response is correlated and bounded (2 MiB request, 512 KiB lifecycle/history response or 8 MiB metadata response, two-second lifecycle / 22-second history exchange deadlines); protocol errors, crashes, and timeouts close/terminate the child, fall back to the Swift parser, and apply a 30-second restart cooldown. No inherited credential environment or shell. Release apps discover only the signed sibling executable. The debug build additionally recognizes the project-local Rust output. `AgentReader` batches selected Codex logs and independently rechecks writer locks and age-based state; worker failure never becomes an empty successful inventory. Claude transcript discovery/parsing runs in Rust; native process identity and descriptor inspection, provider authentication/networking, remote Python execution, and cleanup ownership remain in Swift/platform adapters.
- `script/build_rust_worker.sh`: locked release Cargo build using `rust-toolchain.toml`; the existing app builder includes and signs the worker before signing the app. Swift-only development remains supported through fallback; CI builds the worker and requires integration tests.

- `Sources/BurroCore/WorktreeCleanup.swift`: explicit recoverable cleanup policy and execution. Actionable cleanup statuses use verified local-branch retention independently of integration/publication; ignored data is allowed because all contents are retained. The legacy CLI assessment remains conservative. Fresh scan + identity/Git/activity checks precede the move; branch retention is checked again before and after moving; Codex-managed worktrees are excluded; no force, branch deletion, global prune, or automatic fetch. The main store serializes UI cleanup, disables protection changes during it, and refreshes after batch completion. Recovery and race limits: [cleanup contract](docs/usage.md#cleanup-and-recovery).
- `Sources/Burro/Stores/CleanupBatchStore.swift`: serialized queue with explicit queued/moving/moved/failed/skipped outcomes, optimistic path projection, stop-remaining, and in-memory recovery receipts. It delegates every mutation to the existing WorktreeCleanup actor; there is no safety bypass. AppStore owns multi-selection, confirmation, and a scan generation that invalidates older scans before queuing, then settles optimistic rows only after a fresh post-batch scan.
- `Sources/Burro/Views/CleanupStatusView.swift`: nonmodal progress/results strip, on-demand recovery detail sheet, and multi-selection inspector. Native Table multi-selection, Select ready, Command-Delete/Delete and contextual actions share the same batch review.
- `Sources/Burro/Views/WorktreeCleanupSheet.swift`: one selection-specific confirmation with skipped blockers and retained branches. WorktreeListView exposes folder/branch labels, primary blockers, cleanup filter, and repository-scoped totals. WorktreeDetailView owns the per-repository comparison picker and cleanup entry point.
- `Sources/BurroCore/NotchWorkspace.swift`: machine/path display grouping adapted from PR #1, preserving NotchFeed membership and unread semantics. Orphan-worker buckets have no asserted checkout. NotchView freezes workspace identities alongside held chat rows and shows checkout-level local-ref delivery without filtering on edits.

- `Sources/Burro/App`: app/window/menu bar scenes, macOS activation, and explicit runtime Dock icon from the declared bundle resource to avoid stale Launch Services artwork.
- `Sources/Burro/Views`: navigation, overview, evidence inspector, settings.
- `Sources/Burro/Stores/AppStore.swift`: main-actor state, Git inventories on dashboard open/navigation or explicit refresh, independent local-agent (file changes with 3/15-second fallback) / remote-agent (10 seconds) refresh loops, local preferences, and native open/reveal actions. Repository scans have no repeating timer. Remote results are accepted only when their original host configuration still matches; merged activity never enters the local cleanup scanner.
- `Sources/Burro/Notch/NotchController.swift`: one nonactivating `NSPanel`, screen/Space placement with cross-application fullscreen eligibility, live attention observation, passive local/global pointer movement observers, common-run-loop-mode hover deadlines, pin/collapse lifecycle, provider chat navigation on row click, and explicit dashboard routing. Hover uses global screen coordinates, not SwiftUI/native view enter/exit events. Native menu tracking temporarily extends hover ownership so options menus remain usable outside the panel bounds. The status-bar overlay level is applied after `isFloatingPanel`, which otherwise resets it. Event tokens and pending timers are removed on shutdown. SwiftUI reports measured tab bounds; the controller converts screen pointers to that coordinate space and shares one common-mode timer between panel and preview deadlines. Content resize callbacks defer to the next main-queue turn and combine pending requests, preventing reentrant hosting-view layout during SwiftUI rendering; shutdown cancels pending requests and unchanged geometry is not republished. Already-open page size changes update the native frame and clipping outline together; only opening/closing uses the outline spring, preventing a taller Usage preview from being cut off by the previous Agents outline. Local unified logs record only hover/expansion booleans and event source, never session metadata or coordinates.
- `Sources/Burro/Notch/NotchSurfaceView.swift`: a black `CAShapeLayer`, matching content mask, and two fixed-size SwiftUI hosts. Compositor keyframes own outline, opacity, and a small content translation. The controller grows the native canvas before opening and shrinks it after completion; generation checks ignore cancelled completions. A clipped, steady inner rim glows amber for input requests or blue for unread completions while collapsed. Short opacity/color fades honor Reduce Motion; the rim adds no window area, polling timer, or input target. Hit testing/accessibility explicitly select the active host because layer opacity alone does not hide an NSView from input.
- `Sources/Burro/Notch/NotchView.swift`: compact running-or-scheduled/attention indicators, slim attention queue, explicit worker disclosure, optional idle filtering, persistent Agents/Usage/Mac tabs with temporary hover previews, a separate Usage view with a five-row-height viewport, stable list reconciliation, and machine-scoped monitoring detail navigation. It never owns hover timing or animation. The expanded header retains butter; the compact view has no logo or idle fallback.
- `Sources/Burro/Notch/NotchAgentRow.swift`: fixed-height chat navigation targets with live status and disabled unavailable rows; a parent's worker attention is labeled explicitly.
- `Sources/Burro/Notch/NotchUsageView.swift`: compact Codex/Claude/Grok quota sections, remaining bars, per-provider source age, reset countdowns, explicit stale/expired/missing states, and explicit Claude connection / quota refresh actions. Agent status remains the default notch surface.
- `Sources/BurroCore/ProviderUsage.swift`: provider-neutral quota models, sanitized issue states, and bounded native Codex/Claude response decoders. Multi-bucket Codex values take precedence over the legacy view. Missing percentages/resets stay unknown; account identity, window durations, model quotas, and extra usage are explicit.
- `Sources/BurroCore/CodexUsageReader.swift`: current/legacy desktop CLI discovery before standalone installs and a short-lived, bounded app-server stdio client. Only initialize, account/read, and account/rateLimits/read are allowed. No shell, transcript, model request, listener, or credential export. A single 20-second deadline, 2 MiB output cap, and terminate/kill cleanup bound the child.
- `Sources/BurroCore/ClaudeUsageReader.swift`: read existing Claude Code credentials from the selected local profile or the default account’s exact Keychain item. Requires unexpired user:profile scope. Only the initial read from explicit Connect Claude can prompt; background and token-rotation retry reads forbid interaction. Sends GET to the fixed Anthropic HTTPS usage/profile endpoints with redirects/cookies/cache disabled and bounded response/timeouts. Credentials remain in memory and are never rewritten, independently refreshed, logged, or copied to Burro storage. A 401 triggers one same-profile reread/retry only if the token changed. Expiry or a reset Keychain grant can delegate to ClaudeCLIUsageReader; Claude Code owns renewal. Explicit prompt cancellation does not delegate. Custom profiles never fall back to the default account’s Keychain item. Synchronous credential reads use a dedicated dispatch queue, outside the cooperative executor shared by long-running worktree scans.
- `Sources/BurroCore/ClaudeCLIUsageReader.swift`: bounded, noninteractive, zero-turn `/usage` fallback through the credential owner. Only structured quota reports followed by a successful local-command result are decoded; no prose, transcript, token export, inferred account identity, or history merge. Hooks/tools/MCP/session persistence are disabled, profiles and traffic policy are preserved, and a locked/unknown login Keychain prevents launch. See the [usage connection contract](docs/usage.md#usage-limits).
- `Sources/BurroCore/KeychainAccess.swift`: serialized synchronous scopes enforce the legacy login Keychain process-wide interaction policy in addition to LAContext. Establish no-prompt mode before reading, fail closed if it cannot be set, and restore the previous mode on success or error. Every Burro-native Keychain read must use this scope; no access lists, lock settings, credentials, or trusted applications are changed. A read-only default-Keychain lock check distinguishes temporary lock from denied approval.
- `Sources/Burro/Notch/NotchHealthView.swift`: scoped connection/coverage messages, unverified session titles and evidence, and retry within the panel, avoiding a hover-breaking popover. Unverified sessions remain in the full safety inventory and can be explicitly included in the active queue.
- `Sources/Burro/Notch/NotchTodayView.swift`: compact flat history rows across providers, machines, and projects, with last-active timestamps. The notch menu switches between active chats and today; the choice survives collapse and Usage previews for this app session. Calendar-day filtering uses the viewing Mac's time zone and excludes workers/future timestamps. The viewport keeps the existing five-row cap.
- `Sources/BurroCore/NotchFeed.swift`: explicit same-host/provider parent resolution, nested/cyclic/missing-parent fallback, worker grouping, deterministic attention ordering, and stable list membership with live status reconciliation. Today mode sorts root chats only by updatedAt and stable ID; pending reorders surface Update list without moving pointer targets. Raw session inventory and cleanup decisions remain untouched.
- `Sources/Burro/Views/RemoteHostsSection.swift`: explicit SSH host editor, enable/edit/remove settings, and connection prerequisites.
- `Rust/src/transcript.rs`, `Sources/BurroCore/ChatTranscript.swift`, `Resources/remote_transcript.py`, `Views/Chats/`: in-app chats. The history child's `transcript` request (provider, UUID, at most 3 absolute roots, limit 1–500) locates `<id>.jsonl` (Codex `rollout-…-<id>.jsonl`, Claude `<id>.jsonl`; ≤20,000 entries, `subagents` skipped, symlinks/non-regular files rejected), reads at most the last 16 MiB, and returns display messages: user/assistant text (12,000 chars), tool name + one-line summary (200) + output (600), 3 MiB total; injected AGENTS.md/`<…>` user lines, meta and sidechains are dropped. Only id→path is cached. The Python script applies the same rules over SSH; `OrchestratorTests.testLocalAndRemoteReadersAgree` keeps them identical. `ChatTranscripts` parses Burro chat ids (`codex:`/`claude:` UUIDs, optionally behind `remote:<host UUID>:`) and validates remote batches. `ChatsView` is the list + reader (remote rows never resolve against a local worktree); `ChatTranscriptView` renders bubbles, Markdown, code blocks and expandable tool rows, refreshing working/waiting chats every 4 s while visible.
- `Sources/BurroCore/Orchestrator.swift`, `OrchestratorTools.swift`, `Sources/BurroMCP`, `Stores/OrchestratorStore.swift`, `Stores/AppStore+Orchestrator.swift`, `Views/Orchestrator/`: the orchestrator. One headless Claude Code session (`claude -p --output-format stream-json --include-partial-messages`, `--session-id` then `--resume`) run in its own Application Support folder with a written CLAUDE.md brief. Each turn is one process through `zsh -l` with the prompt on stdin; `OrchestratorEvent` reduces stream-json to text deltas, text, tool calls/results and the final result; the store waits for exit, then reloads history from the chat's own transcript through the Rust worker. `AppStore.orchestratorState()` flattens machines, projects, chats (subagents included), worktrees, to-dos, SSH hosts and profiles into `state.json` before and every 10 s during a turn. `burro-mcp` (bundled, signed) serves `overview`, `list_chats`, `read_chat`, `list_worktrees` and `start_chat` over newline-delimited JSON-RPC from that snapshot; `read_chat` uses `ChatTranscripts`, `start_chat` uses `ClaudeLaunch`/`CodexLaunch`. The orchestrator's own transcript is filtered out of the activity feed and Today (`Orchestrator.owns`). `OrchestratorPage` groups messages into `ConversationTurn`s (question, steps, final answer; earlier replies in a turn become notes among the steps) and shows `OrchestratorAgentsPanel`: machines, chats it started (ids parsed from `start_chat` results), then needs-you/working/unread chats with subagents matched by parent id.
- `Sources/BurroCore/ChatReply.swift`, `ChatMedia.swift`, `Resources/remote_reply.py`, `Resources/remote_media.py`, `Views/Chats/ChatMediaView.swift`: replies and media in Chats. `ChatReply.send` maps `ReplyRequest` (text, model, effort, `ReplyAccess`) onto Codex `turn/start` overrides (after `thread/resume`) or `claude --bg --resume` flags; `CodexAppServer.remote` runs the same WebSocket client over `ssh … sh -c '<fixed proxy command>'` and explains a missing standalone install. Claude replies are refused when `claude agents --json` shows the session open (`claudePlan`), never stopped. `RemoteScript` sends a fixed script with a base64 request line over SSH. `ChatMedia` validates local files and copies remote ones into the per-run cache. `MarkdownBlock.blocks` turns `![caption](/path)` into `.media` blocks; `ChatTranscriptView` groups turns with `ConversationTurn` and folds steps into "Worked for…".
- `Sources/Burro/Notes/`: the Notes window. `GlobalHotKey` wraps Carbon `RegisterEventHotKey` (⌥P; no event taps). `NotesPanelController` owns a floating `.nonactivatingPanel` (moves to the active Space, never activates Burro, swallows ⌘Q) hosting `NotesPanelView`; `NotesPanelModel` handles open/new/duplicate/pin/delete, back-forward history, the ⌘P browser and ⌘K actions, and panel shortcuts (editing keys are sent to the first responder because the Edit menu isn't active). `NoteEditor` is an `NSTextView` over plain text: `NoteEditorStyle` hides `- [ ] ` marks (1 pt, clear, kerned gap) and `ChecklistLayoutManager` draws the boxes; the delegate continues/ends lists, removes marks on ⌫ and keeps the caret out of marks. `NoteText` holds the pure rules (kinds, titles, counts, plain export, open items, toggle). `NotesStore` keeps notes (now with full `text`, pin and opened dates) and skips empty ones on disk; Home's card lists the same notes.
- `Sources/Burro/Views/Home/HomeMainProject.swift`: the featured project card (`AppStore.mainProject`: explicit `home.mainProject` preference, else the repository with the most worktrees) with live/earlier chats from `sessions(inProject:)` (local by worktree ownership, remote by folder name).
- `Sources/BurroCore/RemoteHost.swift`: validated host configurations, namespaced session provenance, connection state, stale sample projection, and safe last-seen retention.
- `Sources/BurroCore/RemoteAgentMonitor.swift`: fixed OpenSSH argument construction, bounded command execution, versioned response decoding, and per-host session identity. Optional Claude desktop/bridge IDs remain compatible with protocol v1 and are validated again before navigation.
- `Sources/BurroCore/Resources/remote_probe.py`: Python 3 read-only probe sent over SSH stdin; macOS/Linux process identity, Codex locks/events/completion envelopes, and Claude metadata/completed-turn evidence. It sends bounded completed history and closed-chat metadata from the past 48 hours alongside live sessions; the extra metadata supports viewer-local calendar days across time zones. AppStore keeps browsing history separate from the active feed; the viewer filters unread results locally, and reserves inspection time for Claude. Remote Claude idle parents additionally inspect parent-scoped subagent lifecycle tails and writable task-output descriptors owned by verified descendant processes (lsof on macOS, procfs on Linux). Bound directory/file/process traversal, retain Unknown for stale unfinished workers or inspection failures, preserve permission waits, and suppress Done while delegated work remains. Scheduled is a distinct state when all owned command branches consist only of shell wrappers waiting for explicit sleep executables; other active tasks win. Executable names, never command arguments, identify the sleep phase. Maintain base provider semantics alongside `AgentParsing`; `script/test_remote_probe.py` covers the Python side. The SwiftPM resource bundle must be copied into the app by the build script.
- `Sources/BurroCore/NotchNavigation.swift`: committed page selection, 160 ms preview entry, 80 ms preview exit grace, click commitment, and preview cancellation on panel dismissal. Selection survives collapse for this app session; preview never writes preferences or changes pinning.
- `Sources/BurroCore/NotchHoverState.swift`: deterministic immediate entry, 120 ms exit grace, reentry cancellation, explicit pinning, and manual-dismissal suppression until exit.
- `Sources/BurroCore/NotchMotion.swift`: analytic critically damped position/velocity, reversal continuity, 120 Hz compositor keyframe sampling, and display-coordinate hover regions with approach/exit tolerance.
- `Sources/BurroCore/AgentChatLink.swift`: allowlisted navigation-only URLs from validated provider IDs. Codex strips its Burro remote namespace and resolves the thread through the provider catalog. Claude prefers this Mac's desktop ID, otherwise its bridge ID; remote desktop IDs and bare CLI UUIDs cannot launch a local session. Missing URLs/Launch Services failures fall back to the Burro inspector; right-click always exposes Show in Burro.
- `Sources/BurroCore/AgentActivity.swift`: fast read-only provider sampling, deduplicated live status counts, and deterministic attention-first ordering. Input requests take priority over unread completions; stale remote samples and completed workers do not create glows. Provider unread state remains authoritative. `AgentSession.isDone` is a presentation projection and does not change lifecycle/cleanup state.
- `Sources/BurroCore/ProviderReadState.swift`: provider-owned unread lists, Codex account selection from non-secret creator metadata, Claude completed-turn metadata, and local/remote projection. Read markers are sampled on the utility task, then reapplied to remote results at each local refresh. Never writes or acknowledges provider state.
- `Sources/BurroCore/ChromiumReadState.swift`: bounded read-only access to the allowlisted Claude preference. CURRENT/MANIFEST selects live tables; indexed blocks, Snappy, CRC32C, WAL sequence numbers, and tombstones avoid stale unread markers. File rotation/corruption fails closed. No LevelDB library, locks, provider hooks, or credential access.
- `Sources/BurroCore/NotchGeometry.swift`: pure camera-safe placement for notched, external, offset, and small displays.
- `Sources/BurroCore/PreferencesMigration.swift`: one-time allowlisted preference import from Grove without overwriting Burro settings.
- `Sources/Burro/Views/Home/`: the landing page. `HomeView` lays out the hero, project/machine cards, inbox, Usage and Mac tiles and the agent dock; while on screen it keeps Mac Health sampling and asks for today's token activity at most every 90 seconds. ## Invariants

1. Background monitoring never mutates monitored repositories or provider configuration. Explicit confirmed cleanup may move an eligible local checkout to Trash and remove only its missing-folder registration, retaining the branch and ignored data; see WorktreeCleanup and the usage recovery contract. Optional usage recovery lets official Codex/Grok tools renew existing credentials. Network access is limited to configured SSH hosts and optional authenticated provider quota reads. No automatic Git fetch, forced cleanup, global prune, or installed hooks. Explicit confirmed sign-in may launch the official coding-app login. Mac Health sampling is read-only; an explicit confirmed action may signal one rechecked same-user process or shut down one simulator.
2. Unknown checks and adapter errors cannot yield a safe candidate. Open idle agents are in use, not disposable.
3. Keep local-ref evidence distinct from verified live remote state. Safe candidate remains advisory.
4. Git commands use fixed executable paths and argument arrays. A repo path/ref is never interpolated into shell source. Read Git status with optional locks disabled and fsmonitor disabled.
5. Agent/session readers never access authentication stores or retain prompt/tool bodies; the Chats page's explicit transcript read is display-only and uncached. Direct usage is a separate, optional path: Codex handles its own authentication; Claude/Grok readers use only selected coding-app sign-ins for fixed provider endpoints. Never export/log/persist tokens, read browser cookies, or independently rotate provider-owned credentials. Grok’s fixed model-list utility and Codex’s account refresh can ask those providers to renew their own stores. Claude renewal stays with Claude Code; the bounded noninteractive `/usage` fallback runs only with an unlocked login Keychain, zero allowed model turns, tools/hooks/MCP disabled, and no saved conversation. It returns quotas, never credentials. No model request is sent. SSH uses existing OpenSSH authentication without importing it into Burro.
6. Manual protection adds a blocker; it cannot override dirty data or other evidence.
7. The frontend never executes shell commands supplied by branch names, filenames, or agent titles.
8. Notch/menu-bar activity is sampled independently of the full Git/worktree snapshot. The fast feed does not loosen cleanup advice between full scans. A session selection preserves the intended worktree when switching dashboard filters.
9. The notch does not take main-window status or activate the dashboard on hover. It uses no global keyboard monitor or provider hooks. Preference changes and screen/Space changes reconfigure the single app-owned panel; shutdown removes observers and the local Escape handler. `AgentNotchPanel.constrainFrameRect` deliberately preserves the frame computed by `NotchGeometry`; AppKit otherwise displaces even a borderless panel below the menu bar. Only the pin button makes expansion persistent; clicks and keyboard opening remain transient after the first pointer visit. Manual collapse does not order the window out and back in. Passive local/global mouse-movement observers remain active across application focus; no per-frame polling, keyboard monitoring, or provider hooks are involved. An 8-point approach margin opens immediately; a 10-point expanded margin and 120 ms exit deadline prevent edge flicker. The expanded interaction footprint remains available during closing for immediate reentry. Core Animation owns outline/fades without per-frame SwiftUI layout or NSWindow resize, preserving both position and velocity when retargeted. Reduce Motion skips interpolation. The native window releases its temporary expanded input footprint after completion. The hosting views disable automatic safe-area and content-size adjustments because geometry already reserves the camera. Safe top insets still reserve a conservative camera gap if auxiliary screen rectangles are unavailable.
10. Remote session IDs include their Burro host UUID; remote paths remain literal, and local worktree resolution refuses remote origins. Offline/expired samples become unknown and cannot count as working. No cloud relay or provider desktop pairing is reused. SSH uses strict host-key checks and batch authentication; the remote command is constant, and metadata never becomes a shell command.
11. Chat navigation only opens fixed provider URL schemes and routes derived from validated IDs. No prompt, folder, credential, CLI import/resume, or remote command is included. Claude remote bridge IDs may navigate the local app; another machine's local desktop ID must never do so.
12. Freeze list membership/order during expanded pointer or keyboard interaction. Keep metadata live, disable missing targets, and expose explicit refresh for pending membership changes. Unfreeze on pointer/key-focus exit; explicit filter/disclosure actions may change layout. Do not acknowledge provider unread markers or infer worker parents from paths/titles.
13. Restore original preferences once, copying only explicit repositories, protections, discovery, and comparison branches. Preserve any already-configured Burro values.
14. The orchestrator runs only while answering a message you sent. Its tools are Burro's MCP server plus Read/Grep/Glob; shell, edit and web tools are disallowed and other MCP servers are not loaded. It starts chats only through the normal launch path, on this Mac, defaulting to Ask before acting. Its snapshot carries no message bodies or credentials.

## Direct usage integration

Burro fetches independently of CodexBar. The Codex contract is generated from the installed app-server schema; the integration uses account/read and account/rateLimits/read. The Claude OAuth usage contract was checked against CodexBar’s [provider documentation](https://github.com/steipete/CodexBar/blob/main/docs/claude.md), but no upstream implementation or dependency is bundled. See [usage setup and limitations](docs/usage.md#usage-limits).

Fetches publish independently as each provider finishes and run in parallel outside the agent loops, at the selected one/five/fifteen-minute cadence automatically and 15 seconds on manual refresh. Poll deadlines are independent per provider: temporary errors retry with 30–300 second backoff, pending renewal is checked after 60 seconds, and rate limits impose at least five minutes even for manual refresh. Disabling Usage clears displayed values and invalidates in-flight results; re-enabling starts a new generation. Each failed provider clears its own previous values, preventing old account data from surviving an authentication failure. Optional account-scoped history persists only for charts; it is never a live quota fallback. Wake/session activation/app activation coalesce into a silent retry of transient failures; rate-limit backoff and healthy-provider cadence remain intact. Expired reset dates never imply a refill. Limits describe the local provider sign-ins and are shared across machines using those accounts, not attributed to individual chats or SSH hosts.

## Known boundaries

This is an unsandboxed, locally signed desktop utility (Apple Development when available, ad-hoc fallback): system process inspection and provider files require normal user read access. App Store sandbox packaging is not implemented. The app store owns the refresh task, so monitoring continues when the main window closes; individual subprocesses have deadlines. Monitoring cannot eliminate time-of-check/time-of-use races, observe unconfigured hosts or cloud tasks, or guarantee all processes are visible. Discovery is bounded rather than a full filesystem crawl; missing directories and private provider schema changes are reported where observable.

Unread integration boundaries and account-switch behavior are documented in [usage guide](docs/usage.md#done-and-unread-status). Keep the Swift and Python completion parsers consistent; completion evidence alone never implies unread.
