# Burro architecture

## Ownership

- `script/generate_brand.swift`: single vector geometry source for the Butter and Abstract mascots, producing production PDFs and transparent PNG/SVG previews. `BurroBrand.swift` loads the butter PDF for the native menu bar; the app icon generator consumes that same PDF. `BurroMascotView` uses separate body/plate PDFs and exported eye geometry for compositor-driven blinking, glances, hops, squash, and tilts. `BurroMascotMotion` keeps poses inside the original frame and the plate stationary. `AgentAvatar` supplies orange Claude/blue Codex tints and a stable per-session timing offset; stale sessions stay still and idle sessions have quieter motion. It stops while collapsed, hidden, clipped, detached, or under Reduce Motion; activity polling does not restart the blink. No animation timer, per-frame SwiftUI update, geometry expansion, or input interception. The build packages and verifies the `Burro_Burro.bundle` assets.

- `Sources/Burro/Notch/NotchGlassView.swift`: one native material for the expanded notch, using `NSGlassEffectView` on macOS 26+ and behind-window `NSVisualEffectView` on earlier versions. `NotchSurfaceView` clips and fades it with the existing outline, hides it while collapsed or under Reduce Transparency, and keeps input routed to the SwiftUI hosts. Camera-area black and nonactivating panel geometry remain unchanged.

- `Sources/Burro/Support/AppAppearance.swift`: shared adaptive palette (warm paper in light mode, charcoal in dark), compact typography, provider badges, card surfaces, and role-aware pill buttons across Home, worktrees, inspectors, remote sessions, Usage, settings, cleanup sheets, and notch content. `AppearancePreference` (Settings → Appearance) sets `NSApp.appearance`; the notch panel pins dark Aqua so the camera area remains black, and `BurroMascotView` resolves tints against its own appearance. Existing sizes, keyboard actions, percentage direction, stale states, safety checks, and panel geometry stay with their existing components.

- `Rust/src/main.rs`: parent-owned `burro-log-worker` stdio executable, the parent protocol and Codex monitoring component. Protocol-v4 JSON requests contain selected Codex log paths and/or a bounded Claude scan request. It reads at most 512 KiB per file, returns lifecycle summaries and file modification times, and caches summaries by device/inode/size/nanosecond modification and change times. Raw transcript bytes are never cached or returned. Appends, truncation, replacement, deletion, and changes during reads invalidate evidence; non-regular files and final-component symlinks are rejected. Cache entries are limited to the current batch (at most 2,048 paths). EOF exits the worker; no listener, daemon, provider credentials, or provider-data writes.
- `Rust/src/catalog.rs`: read-only Codex metadata index using bundled SQLite. A persistent connection compares `PRAGMA data_version` on that same connection; a short transaction reads threads, project roots and worktree attachments consistently without pinning the WAL between refreshes. Main-file identity/stamp changes reopen it. Per-query bounds: 20,000 rows per table, 6 MiB serialized snapshot, 1.2-second progress deadline and 200 ms busy timeout. Only changed metadata crosses the pipe; missing/corrupt/replaced databases or worker restarts cannot revive cached snapshots. `CodexCatalog.swift` retains the recovery reader.
- `Rust/src/claude.rs`: protocol-v4 Claude batches contain a projects root, verified idle session UUIDs/incarnation times, and the current time. Index up to 4,096 project entries once per batch, inspect up to 256 worker logs per session within 1.2 seconds, reject symlinks/non-regular logs, and retain at most 4,096 identity-keyed lifecycle summaries. Freshness is reevaluated on cache hits; terminal handbacks, future timestamps, incomplete scans, and file mutation stay conservative. Swift fallback and remote Python share the project-limit/lifecycle policy. No transcript text crosses the pipe.
- `Rust/src/usage.rs`: separate on-demand history worker with a 20-second scan budget, 20,000 visited entries, 32 MiB files, 256 MiB logical scan budget, 200,000 counter records, and 512 aggregate response buckets. At most 8,192 files / 200,000 parsed records are cached. Discover bounded file candidates and spend the read budget on recently modified transcripts first. Deduplicate provider counters before local-calendar day/model aggregation; retain partial coverage markers. Swift supplies calendar boundaries and reference pricing. No credential reads or transcript text in responses/caches.
- `Rust/src/completed.rs`: bounded Claude desktop metadata scan deserializes only session ID, completion count and archive flag. Cache validated summaries by file identity; incomplete scans fall back to Swift. Bounds: 8,192 visited entries, files below 1 MiB, 256 MiB read budget, 1.2 seconds and 2,048 returned IDs.
- `policy/session-status.json`: single source for Codex lifecycle/completion mappings, Codex age thresholds and Claude status aliases. `script/generate_status_policy.py --check` verifies generated adapters; `policy/status-fixtures.json` supplies independent cross-language expectations.
- `Sources/BurroCore/AgentRefreshCoordinator.swift`: native recursive file watcher, coalesced non-overlapping scans and bounded process-check fallback. Active/uncertain checks remain three seconds; quiet checks use fifteen seconds when the watcher is running. Only process and lifecycle warnings (`AgentActivitySnapshot.samplingWarnings`) count as uncertainty; provider read-state warnings are shown but don't force the fast cadence. Events during scans schedule one follow-up; shutdown cancels pending work.
- `Sources/BurroCore/AgentLogWorker.swift`: serialized child supervision and Swift recovery reader. Each request/response is correlated and bounded (2 MiB request, 512 KiB lifecycle/history response or 8 MiB metadata response, two-second lifecycle / 22-second history exchange deadlines); protocol errors, crashes, and timeouts close/terminate the child, fall back to the Swift parser, and apply a 30-second restart cooldown. No inherited credential environment or shell. Release apps discover only the signed sibling executable. The debug build additionally recognizes the project-local Rust output. `AgentReader` batches selected Codex logs and independently rechecks writer locks and age-based state; worker failure never becomes an empty successful inventory. Claude transcript discovery/parsing runs in Rust; native process identity and descriptor inspection, provider authentication/networking, remote Python execution, and cleanup ownership remain in Swift/platform adapters.
- `script/build_rust_worker.sh`: locked release Cargo build using `rust-toolchain.toml`; the existing app builder includes and signs the worker before signing the app. Swift-only development remains supported through fallback; CI builds the worker and requires integration tests.

- `Sources/BurroCore/WorktreeCleanup.swift`: explicit recoverable cleanup policy and execution. Actionable cleanup statuses use verified local-branch retention independently of integration/publication; ignored data is allowed because all contents are retained. The legacy CLI assessment remains conservative. Fresh scan + identity/Git/activity checks precede the move; branch retention is checked again before and after moving; Codex-managed worktrees are excluded; no force, branch deletion, global prune, or automatic fetch. The main store serializes UI cleanup, disables protection changes during it, and refreshes after batch completion. Recovery and race limits: [cleanup contract](docs/usage.md#cleanup-and-recovery).
- `Sources/Burro/Stores/CleanupBatchStore.swift`: serialized queue with explicit queued/moving/moved/failed/skipped outcomes, optimistic path projection, stop-remaining, and in-memory recovery receipts. It delegates every mutation to the existing WorktreeCleanup actor; there is no safety bypass. AppStore owns multi-selection, confirmation, and a scan generation that invalidates older scans before queuing, then settles optimistic rows only after a fresh post-batch scan.
- `Sources/Burro/Views/CleanupStatusView.swift`: nonmodal progress/results strip and on-demand recovery detail sheet on the Worktrees page. The bulk bar's Move N to Trash… (⌘⌫), a row's context menu and the detail view share the same batch review.
- `Sources/Burro/Views/WorktreeCleanupSheet.swift`: one selection-specific confirmation with skipped blockers and retained branches (and, when every ready folder is measured, the space emptying the Trash frees); every path into cleanup ends here. WorktreeDetailView owns the per-repository comparison picker and cleanup entry point and opens in the Worktrees page's inspector.
- `Sources/BurroCore/WorktreeBoard.swift`, `RepositoryMaintenance.swift`, `Stores/WorktreeInsightsStore.swift`, `Views/WorktreeListView.swift`, `Views/WorktreeBoardViews.swift`: the Worktrees page (the old filter sidebar, `SidebarView`, is gone). `WorktreeBoard` (pure, tested): row kind and state chip (In use, Safe to clean, Uncommitted work, else the eligibility status), which rows can be ticked (not in use, not the primary checkout), filter chips (All, In use, Safe to clean, Uncommitted work, Untouched 14 days+, Protected; unknown activity is never untouched), sort, per-repository groups and the summary; `bulkSet` is the only list the page hands to the cleanup confirmation and holds only rows whose `WorktreeCleanup.eligibility` is allowed. `WorktreeListView` passes `WorktreeBoardModel` values to `WorktreeBoardViews` (header, summary strip, chips and sort, table groups with Show N more past nine rows, bulk bar, repository-health line), shows details in an inspector with "Review each", and scopes to Home's repository/bench filter or the menu beside Sort (All repositories, one bench, one repository). Rows are grouped by repository; state is a chip and a column. `WorktreeTrashKey`: ⌘⌫ opens the Move N to Trash confirmation only while the bulk bar shows, no sheet is open and no text field has focus. `WorktreeInsightsStore` (owned by `AppStore` as `worktreeInsights`): folder sizes (`du`, cached an hour) and object counts (`git count-objects -v`, cached half an hour) measured off the main thread one at a time, driven by the page's `.task` only while it is on screen; unknown stays "—". `RepositoryMaintenance.gcArguments`: `git gc --no-prune --quiet` with reflog, rerere, worktree-prune and prune expiry set to never; run only after the user confirms, one repository at a time, with progress and result kept in the store across page changes. The health line shows when loose objects or packs pass Git's own `gc --auto` thresholds.
- `Sources/BurroCore/NotchWorkspace.swift`: machine/path display grouping adapted from PR #1, preserving NotchFeed membership and unread semantics. Orphan-worker buckets have no asserted checkout. NotchView freezes workspace identities alongside held chat rows and shows checkout-level local-ref delivery without filtering on edits.

- `Sources/Burro/App`: app/window/menu bar scenes, macOS activation, and explicit runtime Dock icon from the declared bundle resource to avoid stale Launch Services artwork. `AppLaunch` owns the store, notch, Notes panel and chat notifications and starts them once at launch, with or without a window; `LaunchKind` (BurroCore, pure) reads the launch Apple event (`aevt`/`oapp` with `keyAEPropData` = `lgit`) to tell a login-item launch, which neither activates nor keeps the window SwiftUI opens. `applicationShouldHandleReopen` shows the window on a Dock click (the always-visible notch panel would otherwise make AppKit do nothing); Window ▸ Burro (⌘0) reopens it. `MenuBarItems` draws the status item's label from `MenuBarStatus` (BurroCore, pure: icon alone, running count, or a needs-you glyph with the number waiting; the newest five non-stale, non-subagent waiting chats); clicking it opens `MenuBarPopover` (`.menuBarExtraStyle(.window)`, replacing the old menu): a "Start a chat…" field whose Return only opens the New chat sheet prefilled in the current project, the waiting chats (opened like notch rows), "N drafts ready" (`BriefDrafts.menuTitle`, opens Home; the label never counts drafts), Keep awake (a clock menu: For 1 hour, For 2 hours, For 4 hours, Until I stop, and Stop keeping awake while a request runs; the While agents work switch; a Stop keeping awake row while a request runs), Open Burro, Today (today's focused time read once per opening when tracking is on), Chats, Notes (⌥P), Show notch (⇧⌘B), Settings… and Quit Burro. Its Keep awake controls act on this Mac, never on agents.
- `Sources/BurroCore/LoginItem.swift`, `Stores/LoginItemStore.swift`: Open at login through ServiceManagement's main-app login item; macOS's status is the only record (reread on Settings, the Today menu and app activation), never saved by Burro.
- `Sources/BurroCore/KeepAwake.swift`, `KeepAwakeScript.swift`, `Stores/KeepAwakeStore.swift`, `Views/KeepAwakeView.swift`: Keep awake. An idle-sleep assertion for an open lid; `pmset -a disablesleep` under a shell watchdog for a closed lid. Contract: [Keep awake](docs/usage.md#keep-awake).
- `Sources/BurroCore/PageHistory.swift`, `Stores/AppStore+PageHistory.swift`: browser-style Back/Forward (⌘[ ⌘]) over `AppPage`, at most 50 entries. Every change of `AppStore.page` is recorded; changes through `go(to:)` (sidebar, shortcuts, menu bar) are direct, anything else a jump whose origin the strip's back pill returns to.
- `Sources/BurroCore/CommandPalette.swift`, `Views/CommandPalette/`: the ⌘K palette. `CommandPaletteModel` snapshots pages, chats (the Chats list), projects, machines and actions once per opening; `CommandPaletteIndex` (pure, tested) folds case and accents and ranks prefix > contains > in-order letters, word starts higher, needs-you > working > other chats, stable ties, 50 results. Actions only navigate, open New chat or Settings, refresh, toggle Keep awake for 2 hours, or prefill the Orchestrator's composer; none sends or launches. The Notes panel keeps its own ⌘K when key.
- `Sources/BurroCore/ChatAlerts.swift`, `Stores/ChatNotifier.swift`: opt-in notifications. `ChatAlertTracker` (pure, tested) turns each agent sample into post/withdraw events: a needs-you or finished state counts after 5 s, ends after 5 s out of it, posts once per episode; chats first seen within 30 s of the first sample are taken as they are; a finish needs work seen in this run; a missing chat is forgotten after 60 s. Subagents and stale remote rows are excluded. `ChatNotifier` posts through `UNUserNotificationCenter` only while its setting is on and macOS allows it, withdraws on episode end, and routes clicks to the chat; it needs the app bundle. A needs-you banner never waits for triage; `updateHeadline` replaces a banner still delivered in place (same identifier, passive) with `ChatAlertText.body` and triage's headline.
- `Sources/Burro/Views`: navigation, overview, evidence inspector, settings.
- `Sources/Burro/Stores/AppStore.swift`: main-actor state (it also owns `worktreeInsights` and `turnClock`), Git inventories on dashboard open/navigation or explicit refresh, independent local-agent (file changes with 3/15-second fallback) / remote-agent refresh loops, local preferences, and native open/reveal actions. Repository scans have no repeating timer. The remote loop probes only hosts `RemotePollSchedule` (BurroCore, pure) says are due: 10 s while a dashboard window is visible, the notch is expanded, or a remote chat is working or waiting, else 60 s; failures back off 15/30/60/120 s (never below the cadence); success, manual refresh or adding/editing a host resets it; the loop rechecks at least every 5 s. Remote results are accepted only when their original host configuration still matches; merged activity never enters the local cleanup scanner. A rebuilt `AgentActivitySnapshot` is published only when `shouldPublish` sees a change views show (sessions ignoring remote sample times, warnings, or a sample time 30 s newer); every rebuild still feeds `ChatNotifier`.
- `Sources/Burro/Notch/NotchController.swift`: one nonactivating `NSPanel`, screen/Space placement with cross-application fullscreen eligibility, live attention observation, passive local/global pointer movement observers, common-run-loop-mode hover deadlines, pin/collapse lifecycle, chat navigation on row click (`ChatOpenTarget.decide`: Burro's Chats page when `openChatsInBurro` is on, the default, otherwise the provider URL; ⌥ flips it; no provider link always opens Burro), and explicit dashboard routing. SwiftUI reports measured tab bounds; the controller converts screen pointers to that coordinate space and shares one common-mode timer between panel and preview deadlines. Content resize callbacks defer to the next main-queue turn and combine pending requests, preventing reentrant hosting-view layout during SwiftUI rendering; shutdown cancels pending requests and unchanged geometry is not republished. Already-open page size changes update the native frame and clipping outline together; only opening/closing uses the outline spring, preventing a taller Usage preview from being cut off by the previous Agents outline. Local unified logs record only hover/expansion booleans and event source, never session metadata or coordinates.

- `Sources/BurroCore/ClaudeUsageReader.swift`: read existing Claude Code credentials from the selected local profile or the default account’s exact Keychain item. ## Invariants

1. Background monitoring never mutates monitored repositories or provider configuration. Explicit confirmed cleanup may move an eligible local checkout to Trash and remove only its missing-folder registration, retaining the branch and ignored data; see WorktreeCleanup and the usage recovery contract. Optional usage recovery lets official Codex/Grok tools renew existing credentials. Network access is limited to configured SSH hosts, optional authenticated provider quota reads, GitHub through `gh`, and Claude Code CLI runs (Shipped summaries, triage, the Orchestrator) under the user's own sign-in. Burro never writes Claude's folder trust on any machine; a remote launch into an untrusted folder is refused before anything starts. No automatic Git fetch, forced cleanup, global prune, or installed hooks. Explicit confirmed sign-in may launch the official coding-app login. Mac Health sampling is read-only; an explicit confirmed action may signal one rechecked same-user process or shut down one simulator.
2. Unknown checks and adapter errors cannot yield a safe candidate. Open idle agents are in use, not disposable.
3. Keep local-ref evidence distinct from verified live remote state. Safe candidate remains advisory.
4. Git commands use fixed executable paths and argument arrays. A repo path/ref is never interpolated into shell source. Read Git status with optional locks disabled and fsmonitor disabled.
5. Agent/session readers never access authentication stores or retain prompt/tool bodies. The Chats page's transcript reads are display-only: the transcript child keeps parsed display messages of up to eight chats in memory (never raw bytes, never on disk); the only transcript bytes Burro stores are its remote transcript copies (invariant 17). Direct usage is a separate, optional path: Codex handles its own authentication; Claude/Grok readers use only selected coding-app sign-ins for fixed provider endpoints. Never export/log/persist tokens, read browser cookies, or independently rotate provider-owned credentials. Grok’s fixed model-list utility and Codex’s account refresh can ask those providers to renew their own stores. Claude renewal stays with Claude Code; the bounded noninteractive `/usage` fallback runs only with an unlocked login Keychain, zero allowed model turns, tools/hooks/MCP disabled, and no saved conversation. It returns quotas, never credentials. No model request is sent. SSH uses existing OpenSSH authentication without importing it into Burro.
6. Manual protection adds a blocker; it cannot override dirty data or other evidence.
7. The frontend never executes shell commands supplied by branch names, filenames, or agent titles.
8. Notch/menu-bar activity is sampled independently of the full Git/worktree snapshot. The fast feed does not loosen cleanup advice between full scans. A session selection preserves the intended worktree when switching dashboard filters.
9. The notch does not take main-window status or activate the dashboard on hover. It uses no global keyboard monitor or provider hooks. Preference changes and screen/Space changes reconfigure the single app-owned panel; shutdown removes observers and the local Escape handler. `AgentNotchPanel.constrainFrameRect` deliberately preserves the frame computed by `NotchGeometry`; AppKit otherwise displaces even a borderless panel below the menu bar. Only the pin button makes expansion persistent; clicks and keyboard opening remain transient after the first pointer visit. Manual collapse does not order the window out and back in. Passive local/global mouse-movement observers remain active across application focus; no per-frame polling, keyboard monitoring, or provider hooks are involved. An 8-point approach margin opens immediately; a 10-point expanded margin and 120 ms exit deadline prevent edge flicker. The expanded interaction footprint remains available during closing for immediate reentry. Core Animation owns outline/fades without per-frame SwiftUI layout or NSWindow resize, preserving both position and velocity when retargeted. Reduce Motion skips interpolation. The native window releases its temporary expanded input footprint after completion. The hosting views disable automatic safe-area and content-size adjustments because geometry already reserves the camera. Safe top insets still reserve a conservative camera gap if auxiliary screen rectangles are unavailable.
10. Remote session IDs include their Burro host UUID; remote paths remain literal, and local worktree resolution refuses remote origins. Offline/expired samples become unknown and cannot count as working. No cloud relay or provider desktop pairing is reused. SSH uses strict host-key checks and batch authentication; the remote command is constant, and metadata never becomes a shell command. Shared SSH connections come only from Burro's own owner-only control folder, so every master was opened with these options.
11. Chat navigation only opens fixed provider URL schemes and routes derived from validated IDs. No prompt, folder, credential, CLI import/resume, or remote command is included. Claude remote bridge IDs may navigate the local app; another machine's local desktop ID must never do so.
12. Freeze list membership/order during expanded pointer or keyboard interaction. Keep metadata live, disable missing targets, and expose explicit refresh for pending membership changes. Unfreeze on pointer/key-focus exit; explicit filter/disclosure actions may change layout. Do not acknowledge provider unread markers or infer worker parents from paths/titles. Burro's own seen marks (`chats.seen`) change only Burro's copy of a chat's unread state.
13. Restore original preferences once, copying only explicit repositories, protections, discovery, and comparison branches. Preserve any already-configured Burro values.
14. The orchestrator's big model runs only while answering a message the owner sent. Its only built-in Claude Code tool is the deferred-tool loader (`--tools ToolSearch`), with file, shell, edit, web and sub-agent tools also disallowed by name, no user/project settings or CLAUDE.md, and no MCP server but Burro's; it reads files only through burro-mcp's `read_file`/`search_files`, confined by `OrchestratorFileAccess` to git repositories and their worktrees, with Burro's data folders, all of `~/Library` and every hidden entry directly in the home folder denied. Automatic triage runs a small model with no tools, MCP servers, settings or saved session, within its daily and hourly caps and Claude-limit floors, and only writes the Brief and proposals. Neither sends a message or starts a chat: `reply_chat`, `start_chat` and triage drafts only write proposals to `actions.json`, and only a Send on a proposal (its card or the Brief) sends it, through the normal Chats reply or launch path (new chats default to Ask before acting; on another machine through `RemoteLaunch`). `reply_chat` refuses a sub-agent and tells the model to address the parent chat; a stored reply to a sub-agent is blocked on every card by `ChatReply.unavailable`. A Send whose outcome Burro can't confirm (`SendOutcome.isUnconfirmed`: a remote start or reply that didn't answer in time, a Codex call that lost its answer after the request left, a local resume or start that didn't finish in time, an answer Burro couldn't read) marks the proposal `unconfirmed`, a terminal state (`OrchestratorAction.recordSend`): the card says "May have gone", offers Open Machines / Open Chats, and "Send again…" only behind a confirmation that a second chat or reply may result; a failed Send again stays unconfirmed, and an identical proposal isn't recorded again. The only changes applied without a Send are its own memory notes and today's to-dos (`add_todo`/`complete_todo`), each shown with Undo. Its snapshot carries no message bodies or credentials.
15. Activity tracking is opt-in and stays on this Mac: no screenshots, OCR, AI or keystrokes; every observation passes `ActivityPrivacy.key` before it is recorded, stored or shown; activity data (including the coverage sidecars, which hold only times) never reaches the orchestrator snapshot, `burro-mcp`, triage input, remote probes, logs or the network (the snapshot has no activity fields, `TriageInput` takes none and blanks Activity paths, the orchestrator has no Claude Code file tools, and burro-mcp's file tools refuse Burro's data folders) (the one-time Dayflow import in `burro-inspect` only writes the local log and prints counts); the sampler does no per-second work and its idle check doesn't run while asleep or locked (the coverage heartbeat only extends an interval in memory and on disk).
16. Nothing outside an explicit click messages, starts or stops an agent. The only triggers are: Start (⌘↩/⇧⌘↩) in the New chat sheet; Send in the Chats composer, on a Home needs-you card, on a notch needs-you card (a click on Send, or Return on text the owner typed or changed; an untouched prefilled draft goes only by the Send button), on the Brief queue or on a proposal card (and "Send again" on a proposal whose first Send went unconfirmed, only after its confirmation); Stop in the Chats header and on a Home working card; and Steer now. Every other entry point (the ⌘K palette, to-dos, notes, worktrees, Retry, the menu bar's "Start a chat…" field, Machines' New chat here, "Ask the Orchestrator about this chat") only opens or prefills a sheet or composer (the Ask prefill goes after a question already written, never over it, and Return doesn't send it untouched). Notifications and the menu bar popover only read chat state and open or prefill things; the popover's Keep awake controls act on the Mac, not on agents. A message reaches exactly the chat the owner approved it for, once: a notch card re-checks before sending that it still answers the chat it shows, and text drafted for a draft that was sent or changed elsewhere is refused; a Send whose outcome Burro can't confirm is never offered again as a one-click Send. Sub-agents never get a reply field or a proposal Send anywhere: `reply_chat` refuses them and `ChatReply.unavailable` blocks every surface, `ChatReply.send` included. A queued reply is sent when its chat goes idle: queuing is the explicit click for that message, which stays visible and cancellable until it goes, dispatch re-runs a normal reply's checks, a message marked as going before a relaunch is never resent, and one whose outcome is unconfirmed is never retried. The only session Burro ever stops without a Stop click is the idle Claude background session of the chat being replied to, as part of that Send (or the message queued for it), only after confirming nothing has it attached; the reply goes only once Claude confirms the stop. Notifications are off until turned on, and banner text (which includes a chat title and, later, triage's headline) is handed to macOS only, never logged.
17. Remote cache: other machines' state is cached owner-only under `~/Library/Caches/Burro/Remote/<host id>/`, excluded from backups and never read or written through a symlink. Cached rows always display as stale until a fresh probe; a host's folder is deleted when it is removed, its address changes or its cache is cleared. Transcript copies hold raw transcript bytes, are written only by the app (never burro-mcp, whose `read_chat` fetches remote chats in full), are capped by size and age and never evicted while on screen; copied bytes are never logged. A just-started remote chat is shown from an in-memory placeholder until a check lists it; placeholders are never written to the cache.
18. Away time is derived locally and never leaves this Mac: `AgentAwayTime` runs in the app over the day scan's per-chat stretches and the tracked day it already holds; the result is not logged, stored, or sent to a worker, the Orchestrator's snapshot, triage or the network. Away time is time Burro was recording while you weren't at the Mac (gaps of 5 minutes or more between your tracked activity), up to when the day was last read. Time Burro wasn't recording, or can't vouch for, is never counted: on days without a coverage record, and before coverage began on the day it was first kept, only gaps between your tracked activity count. Without a tracked day or without stretches (an older worker) it makes no claim rather than reading as idle; a partial total reads "about …".
19. Every Send and Stop listed in invariant 16 goes through the same checks as the Chats composer: `ChatReply.composerPlan` and `ChatReply.send` (or the proposal path) for a reply, `ChatReply.stop` for a Stop, and Home offers Stop only where the Chats header would. A new worktree is created only by Start; one that fails, or whose Starting row is dismissed before the chat starts, is undone (anything the undo can't remove is listed on the row, never silently left), and the chat is not started. Burro never answers an approval; it hands off to the app or terminal that owns it.
20. Bulk worktree clean-up acts only on eligible rows: `WorktreeBoard.bulkSet` holds only rows whose `WorktreeCleanup.eligibility` is allowed, and the confirmation sheet, `AppStore.confirmCleanup` and `WorktreeCleanup.remove` each check again, so bulk is never weaker than one at a time. Repository maintenance never prunes: `git gc` runs only after the owner confirms, with `--no-prune` and reflog, rerere and worktree-registration expiry disabled, so nothing recoverable before it is lost after it; size and object-count measurements are read-only.

## Direct usage integration

Burro fetches independently of CodexBar. The Codex contract is generated from the installed app-server schema; the integration uses account/read and account/rateLimits/read. The Claude OAuth usage contract was checked against CodexBar’s [provider documentation](https://github.com/steipete/CodexBar/blob/main/docs/claude.md), but no upstream implementation or dependency is bundled. See [usage setup and limitations](docs/usage.md#usage-limits).

Fetches publish independently as each provider finishes and run in parallel outside the agent loops, at the selected one/five/fifteen-minute cadence automatically and 15 seconds on manual refresh. Poll deadlines are independent per provider: temporary errors retry with 30–300 second backoff, pending renewal is checked after 60 seconds, and rate limits impose at least five minutes even for manual refresh. Disabling Usage clears displayed values and invalidates in-flight results; re-enabling starts a new generation. Each failed provider clears its own previous values, preventing old account data from surviving an authentication failure. Optional account-scoped history persists only for charts; it is never a live quota fallback. Wake/session activation/app activation coalesce into a silent retry of transient failures; rate-limit backoff and healthy-provider cadence remain intact. Expired reset dates never imply a refill. Limits describe the local provider sign-ins and are shared across machines using those accounts, not attributed to individual chats or SSH hosts.

## Known boundaries

This is an unsandboxed, locally signed desktop utility (Apple Development when available, ad-hoc fallback): system process inspection and provider files require normal user read access. App Store sandbox packaging is not implemented. The app store owns the refresh task, so monitoring continues when the main window closes; individual subprocesses have deadlines. Monitoring cannot eliminate time-of-check/time-of-use races, observe unconfigured hosts or cloud tasks, or guarantee all processes are visible. Discovery is bounded rather than a full filesystem crawl; missing directories and private provider schema changes are reported where observable.

Unread integration boundaries and account-switch behavior are documented in [usage guide](docs/usage.md#done-and-unread-status). Keep the Swift and Python completion parsers consistent; completion evidence alone never implies unread.
