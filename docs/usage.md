# Burro

A small native macOS monitor for Git worktrees and Codex / Claude Code agents, with a live agent panel at the camera notch. Built with SwiftUI, Swift 6, a bundled Rust log worker, and system libraries. Requires macOS 14 or newer. Monitoring needs no additional accounts or hooks; optional usage limits use your existing provider sign-ins. Local monitoring stays on this Mac; remote monitoring uses SSH only for machines you explicitly add.

## Run

```sh
./script/build_and_run.sh
```

Source builds require Swift 6 and Rust through rustup; the repository pins the Rust toolchain. The script builds `dist/Burro.app` and its Rust helper, preserving the existing signing identity (ad-hoc on fresh setups without a certificate). You can launch that bundle directly or copy it to Applications. Other modes: `--build-only`, `--verify`, `--debug`, `--logs`, `--telemetry`.

```sh
./script/build_rust_worker.sh
BURRO_REQUIRE_RUST_WORKER=1 swift test
swift run burro-inspect --agents            # fast agent status, including unread results
swift run burro-inspect                     # JSON snapshot, automatic discovery
swift run burro-inspect /path/to/repository # limit to specified repositories
```

## Agent notch

Local Codex log inspection and Claude delegated-worker discovery/lifecycle parsing run in a private Rust child process, which reuses parsed lifecycle summaries while a file is unchanged. The app still checks live writer locks and event age on each poll. If that child fails, the existing Swift reader takes over and a later poll can restart it. Unverified chats remain protected and appear in Monitoring details, with a count in the notch footer. The active queue omits these rows by default; “Include idle and unverified chats” can show them alongside active chats. There is no separate service to install or configure; the worker exits with Burro.

- The notch is enabled by default. **Hover** over the black strip at the top of the screen to expand it; **click** to open or close; use the **pin button** to keep it open. Move away to collapse an unpinned panel, or use its chevron to collapse explicitly.
- **Agents / Usage** tabs stay visible in the expanded notch. Click a tab to keep it selected, including after closing and reopening the panel during this app session. Hover the other tab for 160 ms to preview it without changing your selection; move away to return. A Preview label and outlined tab distinguish temporary content. Quick crossings do not switch views; clicking during a preview commits it. Collapse/Escape clears any preview, while pinning keeps its existing meaning.
- A steady glow along the compact notch’s lower rim signals attention: **amber for input requests**, **blue for unread completed chats**. Input takes priority when both exist. The glow remains until the provider reports that input is handled or the result is read; hovering the notch does not acknowledge it. It uses short fades without pulsing, switches immediately with Reduce Motion, and adds no extra mouse-catching area. It follows both local and connected remote agents even when Usage is selected.
- The compact notch has two consistent status indicators: running agents on the left (waveform), and attention on the right (inbox: needs input plus Done/unread). It has no logo, name, or idle count. Amber means some attention is input-related; blue means unread completions only. The expanded summary shows the breakdown. When nothing is running but a task is scheduled, the left indicator becomes a teal clock and scheduled count.
- The expanded list groups chats by machine and checkout path (not branch or folder name), with explicit folder and branch labels. Unavailable remote branch metadata is labeled unavailable. Local checkout Git delivery uses cached refs and is never attributed to a single chat. Grouping preserves every visible active/read-only chat, true unread Done results, and parent/worker links; workspace identities stay fixed during pointer interaction. Within that grouping, the list prioritizes **Needs you → Done/unread → Running**, then uncertain activity, Scheduled, and recent activity. The large title and repeated count are removed; up to five complete rows fit. The options menu can include idle chats, refresh status, or open monitoring details. Done results remain until the provider marks them read; merely opening the notch never acknowledges them.
- Codex workers with an explicit parent ID are folded beneath their parent chat. Others, including Guardian runs without that metadata, appear in a collapsed **Background workers** group per machine. Worker input requests promote the group and remain visibly labeled. Counts still represent unique agents, including working/waiting children; grouping does not discard safety evidence or infer ownership from a shared folder. Claude sessions without explicit parent metadata remain separate chats.
- While the pointer or keyboard focus is in the expanded panel, list positions and worker membership stay fixed; titles/status update live. New/disappearing items reconcile after interaction ends, or when **Update list** is chosen. A disappeared row is disabled rather than replaced under the pointer. Selecting a different filter deliberately refreshes the list.
- Click a chat to open Codex or Claude; right-click → **Show in Burro** opens its details. Expand a worker group to open a specific worker. The footer arrow opens worktrees. Missing provider links fall back to Burro details.
- The separate read-only agent poll runs about every 3 seconds after each sample, independently of Git scanning. Footer notices name the affected machine and distinguish history coverage from connection failures. Click a notice for details, last successful remote check, and retry. Unknown/recent is not reported as confirmed running.
- Placement prefers the MacBook's notched display and reserves the camera's physical width. On every display, the black surface attaches flush to the physical top edge, including displays without a camera notch. Concave shoulders and rounded lower corners make it part of the screen edge, with no floating-window shadow. Layout updates when displays or Spaces change; the nonactivating panel joins other apps’ fullscreen Spaces and remains above them without switching apps or bringing the dashboard forward. It stays on your configured notch display; other displays do not get duplicate indicators.
- Hover opens immediately, including an 8-point approach area around the compact strip. The expanded panel has a 10-point edge tolerance and closes 120 ms after leaving. Returning cancels closing immediately. Passive pointer-movement observers work over Burro and other apps, independent of view tracking areas. Core Animation animates the outline and content fades, preserving motion through reversals while text stays at a fixed size. Deliberate collapse stays closed until the pointer leaves and returns. Opening with a click or keyboard does not silently pin the panel.
- Settings and the menu bar let you disable the notch or prefer the main display. **⇧⌘B** opens it while Burro is active. It does not install a global keyboard shortcut or request accessibility/input-monitoring permissions. Clicking inside the panel does not activate the dashboard unless you choose an agent/worktree link.
- The notch deliberately uses a black surface to blend with the camera housing, with restrained sage and amber accents. It respects Reduce Motion and keeps monitoring when the dashboard closes.

Chat navigation uses `codex://threads/<UUID>` and Claude's existing desktop/bridge session IDs. These are navigation-only links: Burro does not send a prompt, import/resume a CLI session, or change remote access settings. Bare Claude CLI sessions without desktop/bridge metadata open their Burro details. Exact Code-session routes were checked against the installed apps; private provider routes can change. See [Claude's URL scheme documentation](https://support.claude.com/en/articles/14729294-open-claude-desktop-with-a-link) for the public deep-link overview.

### Home

The Burro window opens on **Home**. The summary line, chips and cards come from the same live feed as the notch: **running**, **need you** (input requests) and **to read** (unread Done results). Projects are your repositories plus any folder holding an active chat; each card shows live chats, worktree count, folders ready to clean and today's tokens. Machines are this Mac and each remote you added. Click a project for its worktrees, a machine for Mac Health or remote sessions, an inbox row or dock avatar to open that chat (or its Burro details when the provider has no link), and a tile for its page.

"Tokens today" counts local Codex and Claude logs on this Mac since midnight, read by the bundled Rust worker in the background while Home is on screen (at most every 90 seconds). It is an estimate, like the Usage page's local history, and is hidden if the worker is unavailable. Home samples Mac Health only while visible and starts no other polling; worktree inventories refresh on opening Home or Worktrees under the same rules as before.

Use the top bar or **⌘1–⌘8** for Home, Orchestrator, Today, Chats, Worktrees, Machines, Usage and Mac Health. **⌘R** refreshes the current page. **Settings → Appearance** chooses Match System, Light or Dark; the notch always stays dark.

### Home and navigation

The window has its own top bar (drag it to move the window; double-click to zoom), with **Today**, **Home** and the **Orchestrator** (a dot pulses while it works) on the left (with the current page as a breadcrumb), and on the right **Chats** (badge: chats that need you or have results to read), **Worktrees**, **Machines**, **Usage**, **Mac Health** (badge: leftover processes) and **New chat**. ⌘1–⌘8 jump to Home, Orchestrator, Today, Chats, Worktrees, Machines, Usage and Mac Health.

Home sits on an ASCII aquarium that stays put while the page scrolls over it. Your agents are the fish. The species comes from provider and model: Claude Opus is a shark, Fable a sailfish, Sonnet a barracuda and Haiku a minnow; Codex's Sol models are tunas, Astra models angelfish and other GPT models pufferfish. Subagents are small fry that swim beside their parent. Effort sets the variety: low effort darts about with small plain fins, while higher effort glides slower with longer fins, stripes at Extra High and spots at Max (or Ultra). Size is age: a new chat starts as a small fish and grows over its first day. A chat that needs you turns amber and waits at the surface. Scheduled chats, waiting on a timer, are jellyfish that drift almost in place and pulse; their tentacles grow longer with effort. Every other chat from today (idle, done or closed) swims too, darker, so the tank shows the whole day; up to 24 fish, 16 fry and 5 jellyfish, with chats that need you or are working first. Hover a fish or jellyfish in the open water between cards to see its chat, model, effort and age, and click it to open the chat. Model and effort come from Codex's thread index and the end of Claude's transcript, so they show only when the provider records them. The tank animates a few frames a second, only while Home is on screen, and holds still with Reduce Motion. The photo button switches to a glyph or pixel field or a photo (any image or your desktop picture) across the top instead. The chips on the cover open the matching pages. Below: **Chat**, **Project** and **Machine** quick actions, the **Orchestrator**, your **main project**, project and machine cards (gradient tile, live counts or "Quiet"), the plain-language summary, and on the right **To-dos**, the inbox when something needs you, **Notes** (click + or a note to open it in the Notes window) and a **Scratchpad** that saves as you type. The dock shows running and attention avatars (click to open the chat), your machines with status dots, the **+** New chat button, and shortcuts.

### Main project

Home features one project: the repository with the most worktrees, or the one you choose from the card's **⋯** menu. The card shows how many chats are running or need you in it on every machine, its worktrees, folders ready to clean and today's tokens, a **Live** column (working, waiting and unread chats) and **Earlier today**. **New chat** opens the launcher with that project selected; **Worktrees** filters the worktree list to it. It is left out of the project grid below.

### Chats

**⌘4** (or the chat icon in the top bar) lists every Codex and Claude chat Burro sees, on this Mac and your SSH machines: **Needs you**, **Working**, **Ready to read** and **Recent**, with the machine and folder under each title. Search matches titles, folders and machine names. Pick a chat to read it. Each turn shows your message, then a **Worked for 3m 9s** line (open it for the agent's notes and every command, edit or search, with its output; it stays open while the chat works), then the reply with Markdown, code blocks, and any images or videos the agent linked (`![caption](/path/file.mp4)`). Media on this Mac loads in place; from another machine, images copy over SSH automatically and videos when you click **Play**. Click an image to open it. **Open in Codex/Claude** appears when the provider has a link. Chats that are working or waiting refresh every few seconds while on screen.

**Reply** from the composer at the bottom. Return sends, ⌥Return adds a line. Each option starts as "keep what this chat uses":

- **Access**: Ask me, **Approve for me** (Codex reviews its own approval requests), Edit freely, or Read only.
- **Model** and **Effort**: Codex's list comes from its app server on that machine; Claude offers Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1.

Codex replies go through Codex's app-server daemon: Burro resumes the thread and starts a turn (if the chat is working, your message steers the current turn). On another machine the same happens over SSH, which needs Codex's standalone install there (the daemon only runs from it); Burro tells you if it's missing. Claude replies run `claude --bg --resume <id>`, which continues the conversation in the background under the same id. That only works when nothing else has the session open: if it's open in a terminal, the Claude app or as a background session, Burro says so (with **Attach in Terminal** for background sessions) instead of starting a copy. Approval prompts from a reply wait in the agent's own app (or `claude attach`) and show as **Needs you** in Burro.

Burro shows the latest 300 messages, read from at most the last 16 MiB of the chat's file; older ones say so at the top. On this Mac the Rust history worker finds and parses the file; on another machine a fixed read-only script (`remote_transcript.py`) does the same over your SSH connection. Messages are kept in memory for display only. Clicking a chat anywhere else in Burro (Home, Today, the inbox, the dock) opens it here.

### Orchestrator

The **Orchestrator** is one Claude Code chat (Opus 5.5) that Burro runs for you. Open its page with **⌘2** or the sparkles icon in the top bar, or ask from its card on Home: what needs you, where a project stands, what a chat on another machine did, or to get something started. Return sends; ⌥Return adds a line; the stop button ends a turn. **New conversation** starts over (the old one stays in Claude Code's history). The **effort** menu in its header sets how hard it thinks (Low to Max, Extra High by default); it applies from your next message.

The page shows one turn per question: your message, a one-line summary of what it checked (click to open the timeline of steps and their output; it stays open while it works), and its answer. On the right, **Agents** shows your machines with running and waiting counts, the chats it started, then chats that need you, are working or are ready to read, each with its subagents underneath. Click an agent to read it in Chats, or hover and click the sparkles button to ask the orchestrator about it.

Burro runs it with `claude -p` in `~/Library/Application Support/Burro/Orchestrator`, resuming the same session each turn. It gets Burro's tools through a bundled MCP server (`burro-mcp`): **overview** (machines and agent versions, the main project, projects, chats by status with their subagents, to-dos), **list_chats** (filter by status, machine, project or text), **read_chat** (any chat on any machine, read the same way as the Chats page), **list_worktrees** and **start_chat** (a Codex or Claude chat on this Mac in a project folder; it asks before acting unless the orchestrator picks another access level). It may also **Read**, **Grep** and **Glob** files. It can't edit files, run shell commands or browse the web, and it loads only Burro's MCP server, not your other MCP servers. A short turn takes about 5–15 seconds and is billed to your Claude account like any Claude Code chat.

### Benches

Benches group projects the way you think about them. Choose **Group into benches** (or **New bench** once you have some), name it, pick an icon and colour, and tick its projects. Home then shows your benches with their combined running, needs-you and to-read counts (or today's tokens when they're quiet), and the projects that aren't on a bench below them. Click a bench to see its worktrees; right-click to edit or delete it. Benches also appear in the Worktrees sidebar. A project can sit on more than one bench.

### Machines

**Machines** lists this Mac, every SSH machine you added, and every device on your Tailscale network (if Tailscale is installed). Cards show the OS, presence, running agents, project folders and a **Software** list. Tailscale devices you haven't added get **Add over SSH**, which opens the remote-machine form prefilled with the device's tailnet name; SSH machines link to their **Chats**.

**Harnesses** compares agent tool versions across machines: each cell shows the installed version (green = latest, amber = older, grey = not installed) and the latest release from npm next to the tool's name. **Update** asks first, then runs the tool's own updater on that machine (`claude update`, `codex update`, `cursor-agent update`, `opencode upgrade`); chats that are already running keep the version they started with. Versions are re-read at most every ten minutes per machine and npm at most every six hours, only while the page is open.

### Notes window

**⌥P** opens Notes from any app (turn the shortcut off in **Settings → Notes**; the menu bar's **Notes** item and Home's Notes card open it too). It floats over every app and Space without switching away from what you were doing; ⌥P again, Esc or ⌘W hides it, and it reopens on the note you had.

The first line is the note's title. Type `- [ ] ` or press **⇧⌘L** for a checklist: click a box to tick it, Return adds the next item, Return on an empty item ends the list, and ⌫ right after a box turns the line back into text. `- ` makes a bullet and `# ` a heading. Everything saves as you type, to `notes.json` on this Mac.

- **⌘P** browses notes: type to search, ↑↓ and Return to open, pin or delete from the row (delete asks twice). Pinned notes stay on top, the rest by when you last opened them.
- **⌘K** lists every action with its shortcut: New Note ⌘N, Duplicate ⌘D, Send to Orchestrator ⌘J (puts the note in the Orchestrator's composer and opens it), Pin ⇧⌘P, Go Back ⌘[ and Forward ⌘], Toggle Checklist ⇧⌘L, Find ⌘F, Copy as Markdown ⇧⌘C or Plain Text, Add Open Items to To-dos, and Delete Note.

If Burro can't get ⌥P (another app such as Raycast Notes holds it), Settings → Notes says so; free the shortcut there and toggle it off and on.

### Today page

**⌘3** (or **Today** in the top bar) shows one day. The header has a live clock, arrows to step through days and a day button that opens a calendar; past days are read once and kept until you quit. **Status | Project** picks the grouping and **Previews** toggles reply previews.

- **Chats**: everything you talked to that day, grouped by **Status** (Needs you, Working, Ready to read, Earlier) or **Project**, newest first, with the project/worktree path and, with **Previews** on, the first line of the latest reply. Click a row to read it in Chats. Remote chats appear for today but have no preview (their logs live on the other machine).
- **Worked so far**: time from your first to your last message, with one cell per hour (shade = how many messages you sent) and, under it, Dayflow's dominant category for that hour.
- **Messages**: what you sent vs agent replies, across Codex and Claude on this Mac.
- **To-dos**: done today, still open, and added today (today only).
- **Questions for you**: explicit questions agents asked (Codex `request_user_input`, Claude `AskUserQuestion`) plus chats waiting on you right now. Approval prompts aren't written to the logs, so they don't count.
- **Chats**: active chats and the number of projects ("places") they touched.
- **Dayflow** (if installed): focused time, a category bar and the latest activities. Burro reads Dayflow's own `dayflow timeline <date> --json`; activities still waiting for Dayflow's analysis show up later.

Counting runs in the bundled Rust worker's history process while the page is on screen (at most once a minute for today; Dayflow every five minutes) and starts no background work otherwise. Very large transcripts are read from the end.

### Today card

The **Today** card on Home is a deliberately small to-do list. Type and press Return to add, click the circle to tick, double-click to edit, and hover for the delete button (or right-click). Unfinished to-dos from earlier days stay at the top until done; finished ones show until midnight.

Edits apply instantly and queue on disk; if you're offline they upload later, in order, and a retried add never duplicates. To share the list with Maurice, open **Settings → To-dos → Import from Maurice**. Burro reads `CONVEX_URL` and `EDGAR_API_TOKEN` from `~/Dev/maurice-app/Config/Secrets.xcconfig` once, checks them against the deployment, and keeps them in your Keychain (or enter them by hand). While Home is on screen it syncs once a minute and after every change; there's no other polling. Without sync, to-dos stay on this Mac and upload when you connect.

### New chat

**⌘N**, **New chat** on Home, or the dock's **+** opens the launcher. Write the prompt, pick **Codex** or **Claude Code**, the project, the model and effort (Codex's list comes from its app server; Claude offers Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1), and an access level:

- **Ask before acting**: edits inside the workspace and asks before anything else (Codex `workspace-write` + `on-request`; Claude `manual`). Waiting chats appear in Home's inbox and the notch.
- **Edit files freely**: no approval prompts; Codex keeps its workspace sandbox (`never` approval), Claude uses `acceptEdits`.
- **Read only**: reads and plans, changes nothing (Codex `read-only`; Claude `plan`).

Codex chats start on Codex's shared app-server daemon (Burro starts it if needed), so they keep running after the sheet closes and open in the Codex app. Claude chats start as `claude --bg` background sessions; **Attach in Terminal** opens `claude attach <id>`, and `claude agents` lists them. Claude only starts in folders you've already trusted in Claude Code; run `claude` there once if Burro says it isn't trusted. Your last choices are remembered. Starting chats on other machines is not available yet.

### Usage limits

Open **Usage** in the notch for a compact remaining-limit summary, including Claude's separate **Fable weekly** quota when reported. The arrow opens the desktop **Usage** page. The desktop dashboard has an overview and Codex, Claude, and Grok tabs with account/plan labels, full limit bars, resets, optional linear pace markers, extra-usage balances, quota history, and links to each provider's usage dashboard and status page. Burro connects directly; it never reads, launches, or requires CodexBar.

**Account selection matters.** Quotas belong to the account shown on the card, across all its machines. Claude Code can be signed into a different account from Claude Desktop, your browser, or CodexBar. Different totals are then expected. Use **Account → Sign in / switch account** to run the provider's official CLI login in Terminal (after confirming that this changes the coding app's selected account), complete browser authentication, then refresh Burro. Burro does not enter credentials or copy another app's token cache. **Choose existing profile** reads an already configured profile folder; **Use default account** restores the default. Custom Claude profiles must contain their own `.credentials.json`; they never fall back to the default Keychain account. No remote credentials are imported.

- **Codex:** the installed desktop app or CLI provides account metadata and limits through its short-lived app-server connection. Both current `codex-cli/bin/codex` packages and older bundled CLI layouts are supported before standalone installs. No chat, prompt, or model request is sent. API-key-only accounts do not expose subscription quotas. Additional quota buckets remain separate. After a failed quota read, Burro asks the official app server to renew its token and retries once; Burro never rotates Codex credentials itself.
- **Claude:** the default Claude Code Keychain item or selected profile's `.credentials.json` supplies a token with profile scope. Burro requests fixed Anthropic HTTPS usage/profile endpoints with the same token, redirects/cookies/cache disabled, and no credential persistence. Background direct reads disable both modern and legacy Keychain interaction. Only **Allow Claude Keychain access** may ask for a native permission grant.

  Claude Code can reset that grant when renewing its login, even after **Always Allow**. If direct access is denied or the token needs renewal, Burro automatically asks the installed Claude CLI for its built-in `/usage` report. Claude owns credential access and renewal; Burro never exports or rotates its refresh token. This noninteractive command has zero allowed model turns, no tools, no hooks or configured MCP servers, no saved conversation, a private temporary working directory, and a 25-second / 2 MiB limit. It runs only when the login Keychain is known unlocked, preserves the selected profile and nonessential-traffic policy, and never opens a terminal or login flow. Only a successful zero-turn `usage` result with structured quota fields is accepted; prose, insight percentages, and older unsupported CLI output are not treated as limits. Checked with Claude Code 2.1.283.

  The fallback includes live session, weekly and model quotas plus resets. Because the report does not identify the account, Burro labels its source in the desktop view and omits account history and unsupported extra controls rather than borrowing a previous account. Direct access remains preferred when available. A cancelled explicit connection, missing login, locked Keychain, network failure or provider rate limit does not launch this fallback. If the CLI is unavailable or fails, the original actionable state remains. Desktop/browser-only sign-ins are not imported.

- **Grok:** an existing Grok CLI OAuth sign-in in `~/.grok/auth.json` or the selected profile supplies read-only requests to the fixed CLI billing proxy and settings endpoints. If the CLI proxy omits usage, Burro calls Grok’s fixed read-only web billing RPC with the same OAuth token. Product shares are a breakdown of the same subscription quota, not separate limits. On-demand spend is not converted into subscription credits. When an official OAuth token is expired or within five minutes of expiry, Burro runs the installed CLI’s noninteractive `grok models` utility. Grok owns locking and renewal in its original credential store; no chat, model turn, browser login, or copied refresh token is involved. Burro verifies the renewed credential from disk rather than trusting the command’s exit code, coalesces concurrent attempts, and backs off failures. Ambiguous, unsupported, revoked, or unavailable accounts show explicit states. Browser cookies and reset-credit redemption are not implemented. Proto3 zero usage is accepted only when the complete response proves an active current period; missing or malformed data stays unavailable.

**Usage settings** controls provider enablement, one/five/fifteen-minute refresh, remaining versus used display, pace/model rows, and local history. Manual refresh has a 15-second cooldown and respects provider rate-limit backoff. Temporary network failures retry automatically after 30 seconds, increasing up to five minutes; expired Claude credentials are rechecked every minute. After wake, session activation, or reopening Burro, transient failures receive a debounced silent retry; locked Keychains retry every 30 seconds and do not show a Connect button. Healthy providers keep the selected cadence, and wake events never bypass provider rate-limit backoff. Timeouts, rate limits, and pending renewal do not offer a misleading sign-in action. Providers publish as each request completes; a slow account never hides another provider’s available reading. Providers fail independently. A failed fetch clears that provider's old values; disabling Usage or changing profiles invalidates in-flight results. Missing percentages and resets stay unknown; expired reset dates never fabricate a refill. Readings older than ten minutes are stale. Pace uses elapsed time in the reported window and assumes linear consumption; it is a guide, not a prediction of future workload or provider policy.

**Keychain approvals and updates.** Burro’s direct background Keychain reads never show password dialogs. When connecting Claude for the first time, choose **Always Allow** in the native Keychain prompt if you want future approved reads to be silent. Local builds pin their signing identity and designated requirement in ignored `dist/.signing-identity` and `dist/.signing-requirement`. If that certificate is temporarily unavailable, the build stops instead of silently choosing another certificate or ad-hoc signing. A new bundle is verified before it replaces the old one. `BURRO_SIGNING_IDENTITY` remains an explicit override when you intentionally change signing. Moving from an old ad-hoc build can require one new approval. Reusing the same trusted identity avoids invalidating that approval on each rebuild; it cannot prevent Claude Code from rewriting its own Keychain permissions during renewal. The CLI usage fallback avoids depending on that foreign-item grant. Ad-hoc builds or changes to the signing identity can still require approval. A locked Keychain waits for unlock; a revoked provider session or organization policy can still require user action.

**Quota history** keeps up to 30 days / 15,000 samples in a private local file, keyed by a hashed verified account identifier. Charts only show the current account. No email, credential, or chat title is written there. Disable history to delete it, or use **Clear quota history**. Live quotas never fall back to history after an error.

**Local usage & cost** is loaded on demand per provider tab. It reads token counters from the selected local profile, groups daily totals, and shows model breakdowns. Claude request/message identifiers deduplicate streaming responses; Codex counts last-call token events, suppresses repeated cumulative readings, and deduplicates inherited transcript events. The scan is bounded (20 seconds, 20,000 filesystem entries, 256 MiB total, 32 MiB per file, 200,000 records), and shows partial coverage when limits or unreadable files are encountered. It excludes remote work and can include several accounts' logs. Grok only reports cumulative session counters; its total covers sessions updated within 30 days, has no daily attribution, and is never turned into dollars.

Estimated API value uses a small explicit reference rate catalog from [Anthropic](https://platform.claude.com/docs/en/about-claude/pricing) and [OpenAI](https://developers.openai.com/api/docs/pricing), checked September 29, 2026. It assumes standard short-context token rates, handles Claude cache categories, and excludes unknown models, service-tier/context premiums, residency adjustments, and tool fees. The display states priced-record coverage. These values are not charges, subscription spending, or a billing reconciliation. No conversation text or local token history is saved or uploaded by this scan.

### Done and unread status

Burro reads the provider apps' saved unread markers on this Mac. A successful Codex completion event, or an idle Claude desktop session with completed turns, must also be present. Codex internal sub-agent/guardian runs never produce Done notifications, even if they retain unread markers. Live workers still appear as working or needing input. Codex rows prefer the app's saved display name over the original prompt. Working, scheduled, needs-input, unknown, and stale-remote states take precedence. Clicking a row opens the provider; Burro waits for its saved read marker to clear on the next local refresh. It does not mark chats read itself or use a recent-completion timer. Done is separate from worktree safety: an open idle process still keeps its worktree in use.

Codex stores read state per account and execution host in `.codex-global-state.json`. Burro selects the account from the newest thread with creator identity metadata (or the sole saved account on older installations), never unions account histories, and ignores legacy migration snapshots. Switching accounts without creating an attributed thread can leave that selection behind; missing/ambiguous schemas show a visibility warning. The unread-status reader does not access authentication files or tokens.

Claude's `epitaxy-unread-v1` preference is read from its Chromium Local Storage, including manually unread IDs. The reader follows the current LevelDB manifest, sequence numbers and deletion markers, validates checksums, and reads only the relevant indexed blocks. It does not open or lock the provider database. Missing registry/session metadata can prevent a Done badge; unsupported or changing storage fails closed and is retried on the next refresh. The format reader follows [LevelDB tables](https://github.com/google/leveldb/blob/main/doc/table_format.md) and [logs](https://github.com/google/leveldb/blob/main/doc/log_format.md).

Remote SQLite reads can use a stable, journal-free checkpoint when read-only WAL access is unavailable; a changed checkpoint or live journal cancels that fallback. Remote hosts return completion metadata; this Mac applies its own unread list using Codex thread UUIDs and Claude bridge IDs. Local unread IDs are never sent over SSH. Remote Codex completion history shares the existing 2,000-row/inspection-time limits; unread results beyond that coverage may be missing. Another laptop's `local_` Claude ID is never treated as a local read marker. Offline results become Last seen, not Done.

## Mac Health

**Mac Health** (Home's Mac tile, the toolbar, the menu bar, or the notch **Mac** tab) shows CPU use and load, memory used and pressure, swap, startup-disk space, thermal state, and your busiest processes. It samples only while one of those views is on screen: system counters every five seconds, the process list every 15 seconds, and disk space every minute. A covered, minimized or hidden window, or a sleeping display, pauses it.

**Left running** lists things that usually outlived the work that started them:

- **Still busy:** a process outside any app still using at least 25% of a core after an hour of CPU time.
- **Long-running watcher:** a test runner, bundler, or `tail -f` running for over two hours. Jest and Metro worker pools count toward whatever started them; they are listed alone only after that parent exits. Memory figures are physical footprint, the same measure as Activity Monitor.
- **Idle server:** a process listening on a port with no open connections for over 12 hours.
- **Agent script:** a script started from a coding agent's temporary folder over six hours ago.
- **Orphaned:** a process outside any app whose parent exited at least an hour ago.
- **Headless simulator:** a booted iOS simulator with no Simulator window open for over 30 minutes.

Apps, macOS services, common background tools (watchman, syncthing, ssh-agent and similar), open Claude/Codex sessions, and helpers an app or agent started directly are never listed. **Stop…** asks first, then sends a normal quit request only if the process still has the same start time and executable; if it ignores that, the action becomes **Force Quit…**. **Shut Down…** runs `xcrun simctl shutdown` for that simulator. **Ignore** hides that tool in that folder until you choose **Show ignored**. The notch tab only shows a summary; actions stay in the desktop page.

## Use

- Burro automatically discovers repositories from Codex projects, Claude sessions, `~/Dev` (two directory levels), and `~/.codex/worktrees` (three levels). **Add repository** covers other locations. Git's registered worktree list includes inactive, detached, locked, and missing worktrees.
- Filter by working, in use, inactive, safe candidates, protected, or repository. Search branches, paths, and chat titles.
- Select a worktree to see cleanup reasons, live agents, session history, uncommitted changes, ignored data, comparison branch, and local processes.
- Protect a worktree with the lock button. Manual protection is stored in Burro preferences, not Git's lock state. Unprotecting never overrides other checks.
- Finder, Terminal, and Copy Path are available in the detail pane and context menu. Refresh is **⌘R**; add repository is **⇧⌘O**.
- The menu bar uses the fast agent feed. Git/worktree scans repeat 30 seconds after the previous scan completes and run away from the UI thread. Each scan uses at most four Git inspection lanes.
- Settings allows explicit repository roots, automatic discovery, and per-repository comparison branches. Automatic comparison uses `origin/HEAD`, then `origin/main`, `origin/master`, or `origin/staging`.

## Other laptops and servers

Open **Remote sessions → Add remote machine**, or add a machine in Settings. Give it a name and the SSH address/alias you already use, such as `user@laptop.local` or `devbox`. Confirm that `ssh` connects from this Mac first. The remote machine needs macOS or Linux, Python 3, and readable Codex / Claude Code session metadata in the remote user's home directory.

- Both providers appear in the same notch feed, labeled with the remote machine and workspace. Clicking a remote agent opens its chat in the provider app on this Mac when a usable link is available. Codex needs that host/thread in its connected-host catalog; Claude needs its existing remote session bridge. A Claude desktop session ID from another machine is never treated as local. Right-click → **Show in Burro** opens remote details. Local Finder/Terminal actions and local cleanup assessments never apply to remote paths.
- Remote checks run independently, 10 seconds after the preceding check, with at most four SSH processes at once. Slow or unavailable machines do not block local monitoring.
- A failed connection preserves the last observed sessions as **Last seen**, changes their state to unknown, and removes them from working/waiting totals. A sample older than 30 seconds also becomes stale. Pausing a host removes its sessions from the feed. Removing or editing a host cannot reintroduce responses from its old connection.
- OpenSSH uses your existing authentication, SSH configuration, and verified host keys. It runs noninteractively with agent/port forwarding disabled. Burro does not accept unknown host keys, install a helper, copy provider credentials, change provider settings, or open a listener on either machine. It sends a bundled Python reader over standard input and receives session metadata only.
- Codex and Claude's app-to-app pairings do not automatically authorize Burro. This version uses its own SSH connection; provider relay pairings and cloud-hosted tasks are not imported.
- An idle Claude parent, locally or over SSH, remains Running while verified child processes own its session-scoped background task output descriptors, or its subagent logs contain fresh unfinished lifecycle events. Ordinary helper processes and completed workers do not count. Long-running background commands (including servers) remain active until their processes exit. A task waiting in an explicit `sleep` delay shows **Scheduled** with a teal clock, stays in the active list, and does not count as Running or Needs you. This requires a session-owned task branch containing only sleep processes and waiting shell wrappers. Mixed tasks or active workers stay Running; ordinary OS sleeping/idle processes do not imply a schedule. After the delay, the next sample reflects the resumed command or completion. Burro does not infer a wake-up time or import provider scheduling systems. Worker progress expires to Unknown after two minutes without a terminal event; it is never treated as Done merely because the parent is idle. Claude workers can finish with an assistant stop reason or a SubagentHandback tool result marked `toolEndsTurn: true`. Both are recognized locally and remotely, so old completed workers do not keep an idle parent at Unknown. Live background commands and later resumed worker activity still take precedence. Waiting-for-permission status still takes priority. Worker logs predating the parent process incarnation are excluded. These checks inspect event envelopes and descriptor names, never task output or prompt bodies.
- Remote monitoring covers sessions, not remote worktree cleanup assessments. Codex writer locks/turn events and Claude process-start identity use the same conservative rules as local monitoring. Unsupported metadata appears as a visibility notice. Output, record counts, probe duration, and SSH runtime are bounded.
- Remote host names, addresses, optional ports, and enable flags are saved in Burro preferences. Session metadata remains in memory. No passwords, keys, tokens, or transcript message bodies are stored by Burro.

Provider documentation: [Codex remote connections](https://developers.openai.com/codex/remote-connections) and [Claude Code Remote Control](https://code.claude.com/docs/en/remote-control) describe the providers' separate connection models.

## What the labels mean

Activity and cleanup answer different questions: **Inactive** means no observed live use; **Ready to remove** means Burro can preserve the folder in Trash while keeping its commits on a verified local branch.

| Cleanup status | Meaning and next step |
| --- | --- |
| **Ready to remove** | Clean tracked/untracked checkout, no attached live/idle/uncertain chats or processes, successful visibility checks, and a local branch contains HEAD. Moving the folder to Trash keeps that branch. |
| **Local changes** | Modified, staged, or untracked files need saving or discarding. The inspector and blocker sheet show filenames. |
| **In use** | Close the attached chats or processes before removing the checkout. |
| **Protected** | Primary checkout, protected branch, user protection, Git lock, pinned chat, or another registered worktree nested inside. |
| **Archive in Codex** | Use the chat's archive action for Codex-managed worktrees; Burro does not unregister them. |
| **Save commits first** | Detached HEAD has no verified local branch containing it. Create a local branch at HEAD first. A remote-tracking ref alone is insufficient. |
| **Git in progress** | Finish the Git operation or resolve its lock. |
| **Cannot verify** | Missing registration/folder, submodules, incomplete provider visibility, or failed Git inspection. Investigate the specific reason shown. |

These are point-in-time observations; processes can start after a scan. Unknown evidence never becomes ready. Ignored files (including environments and dependencies) do not prevent recoverable removal because the entire folder moves to Trash.

## Cleanup and recovery

Open **Cleanup** to see inactive linked worktrees, with ready folders first. **Ready to remove** filters only eligible checkouts; the sidebar, table, inspector and confirmation use the same readiness decision. The table names the checkout folder and labels its branch explicitly. Header totals apply to the visible worktrees. Use **Select ready** to select eligible rows within the current search and filter, or Command/Shift-click to build a selection. Clear deselects the rows. The multi-selection inspector summarizes ready and blocked items. **Move N to Trash…**, Command-Delete, Delete, and the context menu all open the same batch confirmation.

**Code & commits** separately shows integration evidence and the local branch preserving HEAD. Inclusion in locally available `origin/main`, `origin/staging`, `origin/master`, `origin/develop`, or your selected comparison branch is recognized even when the selected base differs. A small, clean, non-merge history may also be recognized as equivalent patches, including a combined squash. Squash candidates are shortlisted by commit subjects and accepted only when stable patch IDs match. Complex histories, changed titles without a match, timeouts, or output limits remain **Integration not confirmed**; this is not a claim that the PR is open. Burro does not query GitHub or fetch refs automatically.

Use **Compare with** to choose the repository's integration branch. This affects integration context, not whether commits are preserved. **An unmerged or unpushed branch can keep its commits after its checkout is removed.** Burro never deletes that branch. Uncommitted changes, activity, protection, and uncertain inspection still block removal. The older conservative `assessment` in CLI JSON remains an advisory merge/publication assessment; desktop cleanup uses the explicit retention evidence in `facts` instead.

Choose **Move to Trash…** for an eligible checkout or **Show blockers…** for the exact reason a checkout is unavailable. One short confirmation lists every selected folder, its retained branch, and any blockers. Only eligible rows are queued; blocked or changed rows are skipped. Codex-managed paths or attachments must be archived from their chats in Codex instead, even if local changes are the first blocker shown.

Confirmation triggers a fresh scan, verifies the same registration/HEAD/branch, rechecks Git and activity, and verifies the retaining branch still contains HEAD. It then moves the **entire folder** to macOS Trash. Ignored files and symlinks stay in Trash; external symlink targets are untouched. The retaining branch is rechecked before removing only that missing-folder registration, without force or global pruning. Trash must be supported for the folder's volume. If registration cleanup fails or evidence changes after the move, the error gives the preserved location and leaves the registration for manual inspection. No automatic removal occurs. Confirmed batches execute one worktree at a time through these same checks.

After confirmation, queued rows and counts update immediately and the sheet closes. A nonmodal progress strip lets you keep browsing, stop work that has not started, or inspect details. The current filesystem operation completes even after **Stop remaining**. Failed and skipped rows return immediately; a pre-cleanup background scan cannot resurrect pending rows or overwrite the later result. Successful rows remain hidden until a fresh post-batch scan reconciles the list. The result strip retains per-item errors, Trash destinations, kept branch and full commit, and a **Show in Finder** action; there is no success alert to dismiss. Results live in memory until dismissed or replaced by the next batch. A failure after moving the folder reports its preserved Trash location rather than claiming it stayed at its original path.

To restore, create a new worktree on the retained branch (or at the full commit shown for a detached checkout), then copy needed local/ignored files from Trash into it. The `.git` pointer in the trashed folder references the removed registration; dragging it back alone does not repair that registration. Files occupy disk space until Trash is emptied. Emptying Trash is permanent. Fresh checks reduce but cannot eliminate races with other processes.

## Agent detection and limits

- **Codex:** opens the newest `~/.codex/state_*.sqlite` read-only; joins chat workspaces and worktree attachments; inspects existing writer locks without creating them; reads bounded 512 KB transcript tails for turn-start/completion events. Held writer locks plus events distinguish working from open/idle. Recent unfinished events without a lock are marked recent activity, not confirmed running. Missing/unsupported schemas produce a visible notice and prevent cleanup readiness.
- **Claude Code:** reads `~/.claude/sessions/*.json`, verifies the live executable, PID, and process start time, then uses its reported status plus bounded delegated-work checks for idle parents. Dead PIDs are inactive; uncertain or reused identities stay unknown. Unrecognized live status is unknown and protects the worktree.
- **Processes:** uses macOS libproc for same-user process working directories, including terminals and dev servers. The scanner and its descendants are excluded. A nested worktree owns its own activity instead of incorrectly attributing it to the main checkout.
- Provider formats are private implementation details, observed on this Mac in September 2026. Other versions can provide less detail; missing evidence is not evidence of safety. Other users' processes and hosts that have not been added to Burro are outside coverage. Legacy Claude versions without session registries rely on process evidence and show reduced coverage.
- Historical Claude sessions are limited to records retained in the local session directory; Burro does not crawl all old conversations. Codex history includes unarchived database records. The detail pane shows up to ten inactive records per worktree.
- Session titles and filesystem paths remain in memory/UI. Burro persists selected roots, comparison refs, discovery preference, manual protections, notch preferences, and explicit remote host configurations in `local.burro.worktrees` UserDefaults. On first launch after the Grove rename, it imports only the four original preference keys from `local.grove.worktrees` once, without overwriting existing Burro values. CLI JSON contains titles/paths and should be treated as local data. No telemetry is sent. Configured remote hosts receive only the fixed inspection script over SSH.
